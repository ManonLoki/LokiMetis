# ADR：2026-09-07

## ADR-001：在 LokiMetis 内迁移完整的本机 Codex 换皮闭环

- 状态：Accepted
- 关联变更：`FEAT-CODEX-SKIN-MANAGEMENT`，`required_version = 0.2.11`
- 背景：用户要求把独立项目 `bifangcodexskins` 的换皮功能迁移到 LokiMetis，并在 compact 侧边栏增加换皮入口。源项目同时包含换皮、更新、赞助和独立应用壳层，且其主要 Rust 与 React 文件超过 LokiMetis 的硬文件上限，业务规则也尚未按 LokiMetis 的 core-first 边界拆分。
- 决定：迁移皮肤资源库、严格包校验、创建/转换、导入/导出/删除、Codex 实例发现、回环 CDP 应用/停用、定向重启确认和用户触发恢复，保留七套现有内置皮肤及本地生成 Skill。平台无关的清单、值域、安全限制、状态转换和稳定错误下沉到 `loki_metis_core`；Tauri adapter 只拥有应用数据目录、进程、CDP、对话框、拖放与资源解析；React 只拥有展示和交互。
- 决定：换皮作为 `/skins` 一级功能入口加入现有 80px compact 侧边栏，使用 LokiMetis 主题、Tabler 图标、双语资源和现有 AppShell；不复制源项目的可收起侧栏、主题控制器或独立品牌样式。
- 决定：不迁移源项目的 updater、赞助、关于、外部网站、远程日志或远程遥测。皮肤操作不修改 Codex 应用包或用户配置，不连接非回环端点；需重启时只在二次确认后操作用户选中的已验证 GUI 实例。
- 原因：用户需要的是换皮业务闭环而不是第二套应用壳层。按 LokiMetis 既有边界重新分层，能够保留源功能，同时避免引入禁用能力、过度权限、不可维护巨型文件和与 core 静默分叉的业务规则。
- 后果：迁移不是逐文件复制；源项目 API 和内部目录允许重组，但可观察的换皮能力与安全边界必须由回归测试保持。macOS 与 Windows 是本次真实宿主目标；Linux 保持显式不可用，未来支持必须作为新的产品范围批准。

## ADR-002：内置皮肤目录固定为六套并统一作者署名

- 状态：Accepted
- 关联变更：`FEAT-SKIN-CATALOG-MANONLOKI-AUTHORSHIP`，`required_version = 0.2.13`
- 背景：初次迁移保留了源项目七套内置皮肤，但用户随后明确要求移除“极光静界”，并把其余内置皮肤作者统一为 `ManonLoki`。
- 决定：不再打包或展示 `aurora-theme`；其余六套内置皮肤的 `theme.json.author` 精确统一为 `ManonLoki`。用户资源库中的皮肤继续保留各自作者，不在读取、导入或转换时强制改写。
- 原因：内置目录和署名属于产品维护者控制的只读发行内容，统一清单可避免界面显示过时皮肤和大小写不一致的作者身份，同时不侵犯用户主题元数据。
- 后果：现有安装中随旧版本打包的“极光静界”只会在升级安装包后消失；若用户曾另行导入同 ID 的用户皮肤，它仍按用户资源保留。新增或恢复内置皮肤需要新的范围确认与资源校验。

## ADR-003：统一 Agent 启用来源并按能力投影动态界面

- 状态：Accepted
- 关联变更：`FEAT-UNIFIED-AGENT-SELECTION-PANEL`，`required_version = 0.2.13`
- 背景：设置页当前分别展示看板 Agent 与 Hooks Agent 两套复选，重叠的 Codex、Claude Code、Grok、WorkBuddy 可能出现不一致；换皮页也把 Codex 写死为唯一宿主。
- 决定：core 公开 AI 目录继续作为名称、顺序和区域能力映射的唯一事实源，设置页只保留一个 Agent 复选面板。保存时由一个用例把统一选择原子映射到看板采集、WorkBuddy 统计和 Hooks 设置；看板、监控、桌宠与换皮只消费各自支持的子集并动态生成选项卡或空态。
- 原因：用户选择的是“启用哪个 Agent”，而不是分别理解多个内部子系统。单一入口能消除重复控制和漂移，同时不会把 Cursor 伪装成看板数据源，或把不支持换皮的 Agent 伪装成换皮宿主。
- 后果：升级时合并既有看板和 Hooks 的已启用集合以避免静默关停；之后只能经统一命令改变该集合。各区域保留自己的扫描间隔、清理、Hook 目录与展示草稿，不把这些非启用配置混入 Agent 面板；这些配置可以放在对应业务区，不要求与统一面板位于同一路由。

## ADR-004：以同一受限 CDP 边界支持 Codex 与 WorkBuddy 换皮

- 状态：Accepted
- 关联变更：`FEAT-WORKBUDDY-SKIN-HOST`，`required_version = 0.2.13`
- 背景：用户要求换皮除 Codex 外支持 WorkBuddy，并在两者启用时动态显示两个选项卡。本机 WorkBuddy 5.5.3 的打包主进程明确只在 `WORKBUDDY_REMOTE_DEBUGGING_PORT` 为合法端口时开放 CDP。
- 决定：把换皮目标显式建模为 Codex 或 WorkBuddy；两者共享只读皮肤目录、安全资源载荷、回环端点限制、有界连接和清理生命周期，但分别执行应用身份、进程、启动参数与页面标记验证。WorkBuddy 只通过官方环境变量打开回环调试端口，不读取账户资料，也不复用 Codex 页面判断。
- 原因：复制一套换皮服务会产生资源规则和清理逻辑漂移；完全放宽现有 Codex 判断又可能把皮肤注入未知 Electron 页面。显式宿主类型能共享安全机制并保持身份隔离。
- 后果：选项卡、实例选择、活动状态和后台维护任务按宿主隔离。兼容皮肤在 WorkBuddy 上只保证通用 CSS/资源注入，Codex 专属选择器缺失时以兼容性降级呈现，不伪造完全一致；Linux 仍明确不可用。

## ADR-005：Hooks 配置归属监控区并使用任务导向的一级入口名称

- 状态：Accepted
- 关联变更：`FEAT-MONITOR-HOOKS-NAVIGATION-LABELS`，`required_version = 0.2.13`
- 背景：统一 Agent 选择后，Hooks 目录与写入表单被一并放入公共设置页，导致监控业务配置脱离工作台、监控管理与图片管理；一级入口的“看板”“监控”“换皮”也未完整表达用途。
- 决定：统一 Agent 复选面板继续只保留在公共设置页；Hooks 目录、配置文件与写入操作移至 `/monitor/settings`，作为监控区第四个二级选项卡且不复制启用复选。三个一级业务入口分别命名为「用量看板」/「Usage Dashboard」、「AI监控」/「AI Monitor」、「应用换皮」/「App Skins」。
- 原因：Agent 是否启用是全局选择，而 Hooks 如何落盘是监控领域操作；分开归属能保持单一选择源，同时让用户在执行监控任务的上下文中完成配置。任务导向名称也能在 compact 侧栏中更清楚地区分用途。
- 后果：公共设置页不再显示 Hooks 配置表单；监控区恢复设置子路由。一级入口只改变可见名称，不改变路由、图标、顺序、默认落地页或底部设置入口。

影响、验证与风险：产品行为、协议、依赖、应用身份和用户数据不变；新版本日志如实说明为维护重发。各平台必须重新执行非空全量单元测试与最终包校验，macOS继续Developer ID签名、App/DMG分别公证及附票。关闭E2E只代表本次不执行安装和交互验收，未运行项保持Unverified；实际构建失败不能公开为成功。发布审查绑定本次sourceHead，候选证据只写忽略的release目录。

恢复与结束条件：新版本完成Git发布及本次渠道分发后例外结束；相同稳定ID重试不重复升版，旧tag绝不移动。若构建失败保留失败证据并在相同冻结源码上恢复；回退渠道应重新核对旧Release身份并另行明确操作，不删除或改写既有发布记录。

## ADR-20261022-004：Cursor Token 采用独立账户分项来源

状态：用户已明确批准。change_id：`LMDESK-CURSOR-TOKEN-USAGE-001`；分类：feature；required_version：`0.8.0`。确认来源：本次对话实测云端事件后，用户要求“增加支持”。

背景：Cursor 的额度比例与 Token 事件是不同接口；本机文件来源枚举及现有 TokenUsage 模型不能表达账户跨设备归属及部分缺失缓存字段。直接并入本机总量或把缺失缓存当零会制造完整性事实。

决定：在看板新增独立 Cursor 账户入口，core 拥有分页完整性、事件唯一性、四分项缺失计数和日期/模型聚合；GUI 复用既有只读登录材料、固定允许主机的 curl/sqlite3 进程驱动、应用后台 owner 与查询代次。原始上游字段分别汇总，不推断完整总 Token。范围、限额和成功标准统一见[产品规格](../product_spec/20261022_product_spec.md#cursor-账户-token-明细)。

取代范围：只补充既有“Cursor没有本机Token来源时不虚构分量”的边界，既有本机全部、通知和终端数据合同保持不变。云端统计不会伪装为本机扫描结果。

风险与验证：网页接口没有个人账户稳定公开契约，可能变化、延迟或缺失明细；格式变化与不完整分页失败关闭。单元回归覆盖分页、缺失/零、日期、溢出、账户隔离、节流、取消与原生按钮归属；真实上游可读取只证明当前账户与协议可达，单元测试不等同最终候选验收。Windows/Linux 未实机验证，依赖既有 curl/sqlite3 发现方式。

恢复条件：可撤回独立入口及其内存读取模块，无新增业务数据库、用户配置或凭据迁移；既有额度入口继续独立工作。未来若要合并终端、本机总量或补全完整Token口径，须另行定义归属与缺失语义。

验证与调整：本次工程回归和真实Actions结果分别报告，未执行项不得记为通过。将来变更矩阵、签名身份、凭据来源、渠道或发布后动作时须有明确新决定；可恢复local_package，但不改既往发布快照。

## ADR-20261021-017：Claude额度取自statusLine，Cursor账单月进入月窗口

状态：用户已批准并接入源码。change_id：`LMDESK-QUOTA-CLAUDE-CURSOR-MONTHLY-001`；分类：feature；required_version：`0.7.2`。确认来源：用户确认“Claude 与 Cursor 读取本机信息获取周/月额度”方案，并说明 Cursor 按月、其它提供商按周；协议直接升级，不做旧终端能力协商。

决定：活动读取顺序改为Codex、Claude、Cursor、Grok。Claude Code 的 statusLine 输入自带订阅额度 `rate_limits.five_hour/seven_day`，Hook配置为 Claude Code 额外写入受管 `statusLine`，命令沿用 relay 参数形状并使用伪事件 `StatusLine`；relay 只把两个窗口的 `used_percentage` 与 `resets_at` 原子写入 rendezvous 同目录的私有 `claude-rate-limits.json`（0600），不输出状态栏文字，也不投递到监听器。用量服务只读该记录，丢弃已过重置时刻的窗口；Claude 不读取钥匙串或OAuth令牌，也不发远程请求。新增 `monthly` 窗口种类，按27～32日归类，只有 Cursor 保留，其它提供商的月度周期仍丢弃。

取代范围：取代ADR-20261021-011与013中“Claude 不查询、不出现用量卡”和“月度账单一律不展示”的约束；本地优先、凭据只读、主机允许列表与五分钟节流不变。

取舍：statusLine 是单值配置，只在用户没有自己的 statusLine 时写入；用户已有 statusLine 时不接管，Claude 额度保持不可用。记录只在 Claude Code 运行并收到响应后更新，API Key 登录没有该字段。桌面向终端下发的额度可能含 `claude` 提供商与 `monthly` 窗口，旧终端严格校验会整体拒收额度，须与终端同版升级。

验证与恢复：core 额度、Hook 生成/合并/清理与 GUI relay、本地记录、工作台渲染回归覆盖。未在真实 Claude Code 会话或真实 Cursor 上游验收，未验证 Windows/Linux。可回退本条提交；已写入的受管 statusLine 由 Hook 清理入口按标识移除。

## ADR-20261021-016：配对恢复使用持有者强恢复码与明确本地授权

状态：用户已批准并接入源码。change_id：`FEAT-PAIRING-RECOVERY-V1`；分类：feature；required_version：`0.7.2`。用户在重装配对排查后确认桌面正式/测试实例区分及加密配对恢复包。

## ADR-20261021-012：用量优先读本机记录读不到再走远程

状态：用户已提出并授权实现。change_id：`LMDESK-MONITOR-QUOTA-LOCAL-001`；分类：feature；required_version：`0.7.0`。确认来源：用户要求用量数据优先从本地信息获取，无法获取再考虑远程接口。

背景：ADR-20261021-011 让工作台显示四个提供商的 5 小时与周剩余，当时的读取直接使用登录材料访问用量接口。Codex 会话记录和 Grok 用量日志里可以出现可归类的窗口；Cursor 与 WorkBuddy 的常见本机缓存不含这两种窗口。

决定：同一次用量读取先解释本机已有记录。只要得到 5 小时或周窗口之一，就采用该结果，并且不再发远程请求，也不为另一种缺失窗口补请求。两种都没有时，才沿用 011 的只读凭据、官方客户端标识和 HTTPS 主机允许列表。Claude 仍不查询。月度、单独结束时间和无限额度仍不标成周用量。本地读取不改写来源文件，不解 WorkBuddy 加密信封，不读取密钥材料。Cursor 只查询状态库中明确的用量摘要键；WorkBuddy 只接受用量数据目录里能归类的记录。没有这类字段就视为本地未获取。

取代范围：收窄 ADR-20261021-011 中“直接用登录材料请求远程用量”的来源顺序。011 关于展示文案、Claude、窗口归类、加密信封、令牌和刷新节奏的约束仍然有效。

影响与理由：本机已经记下的短窗或周窗口不必再打远程；没有这类记录时行为与 011 相同。Cursor 与 WorkBuddy 在常见安装上仍会走远程，因为它们的本机文件不含目标窗口。不新增 HTTP crate。

风险与验证：macOS 上 core `provider_quota` 17 项通过，其中包括 Claude 不在用量提供商内。GUI 夹具证明本地窗口命中时远程程序不启动，本地缺失或仅月度时才使用远程窗口，远程也没有目标窗口时不把月度记成周用量，来源文件字节不变，加密登录在没有本地窗口时不被破解。jsonl 尾部切在 UTF-8 续字节上、更旧的目标窗口排在 8 个无窗口文件之后、以及 Cursor 两个摘要行同时存在时，仍采用本地窗口。未启动完整 GPUI 进程，未连接真实上游，未在 Windows 或 Linux 验证。

恢复与调整：若要恢复为始终远程，去掉本地优先分支即可，011 的远程路径仍在。按窗口分别用远程补齐，或把月度显示成周用量，都须另行确认。

## ADR-20261021-005：图片魔数表唯一归属 pairing，格式值域留在 core

状态：已确认并实施。change_id：`LMDESK-IMAGE-BMP-WEBP-001`；required_version：`0.6.0`。确认来源为用户当日选择“记为当日 ADR”，并确认保留 `image-webp` 直接依赖。

背景：BMP/WebP 接入后，本机图库（core `ImageFormat::from_bytes`）与设备资源传输（pairing `AssetDescriptor`）各维护一份魔数判定，且 pairing 校验另有一份 MIME 白名单；新增格式需多处同步，两侧可能对同一字节得出不同结论。core 已依赖 pairing，反向依赖会形成循环。

决定：魔数到 MIME 的识别表只在 `loki_metris_pairing::assets::sniff_image_mime` 登记一份，pairing 的识别与校验共用此表；core 的 `ImageFormat::from_bytes` 调用它并按 `mime_type()` 映射回格式。格式枚举、扩展名、展示名与 `ALL` 顺序仍由 core 唯一维护，GUI 只派生，不再手写格式列表。动态与静态 WebP 在解码像素前经 `image-webp` 读取容器头完成帧数和内存预算，`image-webp` 与 `image` 共用同一锁定版本。

影响与代价：pairing 成为图片字节识别的底层事实源，新增格式需在 pairing 表与 core 枚举两处登记；core 若有 pairing 表外的格式会识别失败而非被误判。主题与皮肤的 PNG/JPEG 范围是独立产品值域，不受本条约束。图库目录 JSON 结构保持不变。

理由：不引入新 crate 即可消除重复判定，并保证本机图库与设备传输对同一字节的判定一致。替代方案“把格式枚举下沉到 pairing 再由 core 重导出”会把图库领域类型放进传输层，暂不采用。

验证：core、pairing 与 GUI monitor 相关单元测试在 macOS 本机通过；未执行打包、实机或其它平台验证。恢复：如传输层需要与图库不同的格式范围，在 pairing 表与 core 枚举之间增加显式映射或拆分值域，并更新本条。

## ADR-20261021-001：终端联动采用桌面数据服务与纯局域网恢复

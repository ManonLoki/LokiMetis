# ADR：2026-09-30

## ADR-001：以 design-taste-frontend-v1 的视觉语言调整整个 GUI

- 状态：Accepted；用户于 2026-09-30 明确要求以 `design-taste-frontend-v1` 作为 UI 标准调整整个项目。
- 背景：原主题以 indigo 为主色，却在导航、图表中混用暖红/橙，中性色冷暖不一，卡片阴影偏重且缺少统一的动效缓动。
- 决定：采纳该 skill 中与现有技术栈兼容的部分：单一暖红品牌色阶、统一暖灰中性色、无纯黑背景、带背景色调的宽扩散阴影加 1px 内侧高光、`cubic-bezier(0.16, 1, 0.3, 1)` 缓动、页面区块错峰上浮入场、按钮按下反馈、可见焦点环。Mantine 圆角令牌调整为 `sm 0.5rem / md 0.75rem / lg 1.25rem / xl 1.75rem`（原为 Mantine 默认 `sm 0.25rem / md 0.5rem / lg 0.75rem / xl 1rem`），因此普通 surface 由 12px 变为 20px。
- 后续授权：用户于同日明确授权采纳此前未采纳的部分并修改相应门禁。据此：图标库由 `@tabler/icons-react` 改为 `@phosphor-icons/react`（全局 `regular`，共 22 个图标替换，内联 SVG 复制图标一并替换）；新增 `motion`（磁吸按钮 `Magnetic`、卡片入场与 layout 换位 `MotionItem`、仅用于扫描进行中的 `BreathingDot`）；新增 Tailwind v4（仅 theme 与 utilities，不含 preflight）；新增自托管 `@fontsource-variable/geist` 与 `geist-mono`，Token 数字使用等宽字体。同步修改 `docs/ENGINEERING_RULES.md`、`docs/RUST_GUI_TEMPLATE.md`、`tauri_gui.md`、`tauri_sidebar.md` 中的对应门禁。
- 仍未采纳：整体不对称布局、无限循环微动画铺满所有卡片、Tailwind 取代 Mantine 主样式。`tauri-gui-sidebar-compact-80-v1` 的像素保持不变，仅把图标属性由 `stroke = 1.75` 改为 `weight = "regular"`。
- 风险与恢复：所有动效仅在 `prefers-reduced-motion: no-preference` 下运行；恢复标准值只需还原 `AppThemeProvider.tsx` 的 `radius` 与相关 CSS。
- 进一步调整（同日）：新增图表折线描绘与柱条生长、面板光标聚光（`useSpotlight` 只写 CSS 变量）、数值变化滚动（`CountUp`，首次挂载不动画）、表格行悬停染色、侧栏图标悬停弹性、空状态图标缓慢浮动、皮肤目录骨架屏；全部在 `prefers-reduced-motion: no-preference` 下运行。清理未被引用的 CSS（`hero-panel`、`workspace-card`、`brand-*`、`initialization-*` 等）与未使用的主题变量，并把 `source-*-column`、`calls-*`、`empty-state`、`local-hero-card` 等小样式迁移为 Tailwind 工具类。精简 65 处说明性界面文案（中英同步），保留信息本身、去掉解释性铺垫。
- 全页面统一（同日）：内容面板合并为同一套材质（暖白底、暖边框、宽扩散阴影、顶部内侧高光，悬停时边框染色、阴影加深并带光标聚光），不再区分 `surface-card` 与数据面板；移除紫色阴影与所有 `violet` 用法，状态色收敛为 error=red、success=teal、warning=yellow、info=blue、品牌与中性标签=brand/gray；监控导航链接与看板导航链接共用同一组悬停/选中令牌；所有 Tabs 采用同一分段胶囊样式（由主题默认 `className` 提供）；未指定颜色的 Alert 默认改为中性灰，避免与品牌红的错误提示混淆；各页面根容器间距统一为 `lg`，路由内容区块统一错峰入场。
- 导航、筛选与加载统一（同日，用户明确要求）：监控页与换肤页顶栏改用与看板相同的粘滞顶栏与导航链接样式，所有 Tabs 采用同一导航链接观感，悬停为中性底色、选中为品牌底色；看板「图表」与「用量」页的窗口与分组筛选合并为单行 `FilterBar`；同页多张数据表共用 `data-table` 列宽使表头对齐；概览页移除「本机记录」可见标题（保留可访问名称）；页面级与列表级加载态由转圈与遮罩面板改为骨架屏。
- 移除「恢复上次使用的皮肤」（同日，用户明确要求）：删除 `lib/skin-preference.ts`、页面提示与相关会话状态和中英文文案。该记忆仅保存在 WebView 的 localStorage，旧键 `loki-metis.remembered-skin.v2.*` 不再被读取，也不再清理。

## ADR-002：移除 GUI 发布性能门禁

- 状态：Accepted；用户于 2026-10-01 明确要求把性能门禁整套逻辑移除。
- 背景：发布流程原有 `performanceSelection`、`gui-release-v2` 探针、`performanceEvidence` 与 `performanceRuntimeBinding`，需要在 GUI 内注入观测代码并在 manifest 中携带证据。
- 决定：删除 `$desktop-test-gui-release-performance` Skill 及其校验脚本；删除 Tauri 侧 `performance_evidence` 模块（三个 IPC 命令、环境变量启用、主窗口可见性事件与初始化脚本）和前端 `lib/performanceEvidence.ts` 及其测试；`main.tsx` 直接启动应用。同步修改 `AGENTS.md`、`docs/AGENT_POLICY.md`、`docs/ENGINEERING_RULES.md`、`docs/RELEASE.md`、`docs/RUST_GUI_TEMPLATE.md`、`README.md`，以及发布相关 Skill 与升级器测试；`.harness/upstream-lock.json` 移除该 Skill 的托管条目。发布信封只保留 `reviewSelection` 与 macOS 签名选择，manifest 不再含任何 `performance*` 字段。
- 风险与恢复：发布前不再有冷启动、CPU、内存与 Long Task 的机械把关，性能退化只能靠日常使用发现。上游 Harness 若再次升级，被本次修改的托管 Skill 文件会与锁定哈希不一致，需要在升级预览时明确保留本决定。恢复需重新引入该 Skill 与探针模块并更新发布文档。
- 版本：维护性移除，不单独提升版本；随 `BUG-UI-UNIFIED-REDESIGN-20261001` 一并发布。

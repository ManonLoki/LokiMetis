# ADR：2026-09-08

## ADR-001：用量参数归属看板专用设置子页

- 状态：Accepted
- 关联变更：`FEAT-DASHBOARD-SOURCE-SETTINGS-TAB`，`required_version = 0.2.14`
- 背景：公共设置原同时承载全局 Agent 启用选择、宿主偏好与用量扫描/保留参数。用户明确要求把“扫描间隔”与“自动清理”移到“用量看板”，并在“数据源”后新增“设置”选项卡。
- 决定：公共 `/settings` 继续作为应用、语言、主题、通知、自启、本地更新日志与唯一 Agent 启用选择的全局入口，不再展示两项用量参数。新增 `/dashboard/settings`，在物理 Agent 与 WorkBuddy 视图中紧跟“数据源”，且只承载扫描间隔与自动清理；“全部”视图不显示不适用的设置子页。
- 决定：两项配置仍是全局设备偏好，不因当前 Agent 选项卡而变成每 Agent 独立数据。既有 core 值域、持久化、IPC、后台扫描/清理时机与错误语义保持不变；本次只调整 React 路由、导航和展示归属。
- 原因：扫描节奏与派生数据保留直接服务用量采集与索引，放在数据源相邻的任务上下文更易发现；保留全局语义则避免重复配置或与 core 权威状态分叉。
- 后果：用量看板多一个子路由，导航需锁定“数据源 → 设置”顺序，切换到“全部”时需退回概览。公共设置与用量设置必须分别有去重回归，但不需要新增 core、Rust command、持久化结构或依赖。

## ADR-002：换皮工具栏移除显式进程选择与结果计数

- 状态：Accepted
- 关联变更：`FEAT-SKIN-TOOLBAR-SIMPLIFICATION`，`required_version = 0.2.14`
- 背景：换皮工具栏同时展示搜索、宿主进程下拉框、仅看用户皮肤和资源操作，列表下方另显示筛选结果数量。用户通过截图明确要求删除进程下拉框和“显示 N 个皮肤”计数。
- 决定：工具栏只保留搜索、仅看用户皮肤、导入、创建主题与刷新；删除宿主进程下拉框、其会话选择状态和专属双语文案，同时删除资源结果计数及专属双语文案。
- 决定：目标选择收敛为“唯一实例自动使用”。多个同宿主实例并存时不得按顺序、PID 或端口静默选择，任何需要目标的换皮操作都保守阻止，并提示用户关闭多余实例后刷新重试。
- 原因：删除用户指定的冗余控件与计数可以降低工具栏密度；唯一实例规则保留常见路径，同时避免在没有显式选择入口时误操作其他正在运行的宿主实例。
- 后果：换皮页不再支持在多个并存实例间直接选择目标；用户需要先把目标宿主收敛为一个实例。实例发现、身份验证、回环 CDP 与后端多实例拒绝继续存在，不新增静默默认值或权限。

## ADR-003：安装显示名本地化但稳定包身份保持英文

- 状态：Accepted
- 关联变更：`FEAT-LOCALIZED-PACKAGE-DISPLAY-NAME`，`required_version = 0.2.16`
- 背景：用户明确要求中文环境显示“诡秘神谕”、英文环境显示“LokiMetis”；Windows 以安装时选择语言为准，macOS 以系统语言为准。安装包和 DMG 的物理文件名在目标机器选择或解析语言前已经生成，不能按目标用户语言动态变化。
- 决定：Windows NSIS 显示 English/简体中文语言选择器，以所选语言本地化安装器标题、安装/卸载文案、开始菜单与桌面快捷方式以及“已安装的应用”显示名。macOS 在 bundle 中提供 English 与 `zh-Hans` 的 `InfoPlist.strings`，由 Finder 按系统首选语言解析应用显示名，其他语言回退 English。
- 决定：全局 `productName`、安装包与 DMG 文件名、`.app` 目录名、Windows 安装目录与注册表键保持 `LokiMetis`。这些值是升级、卸载、签名、候选摘要和自动化定位所需的稳定身份，不受用户可见语言影响。
- 原因：把本地化限制在系统支持的展示层，可以满足用户语言体验，同时避免同一应用因重装时选择不同语言而形成并行安装、孤立注册表键或不可追踪候选。
- 后果：资源与配置解析测试可以证明两种语言映射和稳定身份边界；Windows 安装器实际选择流程与 macOS Finder 切换仍需在对应最终候选 E2E 中验证，不能由源码检查冒充宿主验收。

## ADR-004：换皮页移除显式启动与用户皮肤专属筛选

- 状态：Accepted
- 关联变更：`FEAT-SKIN-LAUNCH-AND-USER-ONLY-REMOVAL`，`required_version = 0.2.16`
- 背景：换皮页在 Codex 与 WorkBuddy 选项卡中会按宿主运行状态显示独立“启动”按钮，工具栏还提供“只看用户皮肤”筛选。用户根据实际页面截图明确要求两类宿主均删除启动按钮，并隐藏该筛选。
- 决定：Codex 与 WorkBuddy 共用的换皮界面不再渲染显式宿主启动按钮，也不再保存或执行用户皮肤专属筛选；同步删除专属双语文案、纯前端运行状态查询和不可达会话字段。工具栏收敛为搜索、导入、创建主题与刷新。
- 决定：皮肤“应用”动作在未发现实例时仍可沿用既有受限宿主启动流程，以完成用户明确触发的换皮任务；唯一实例自动目标、多实例保守阻断、重启风险确认和回环 CDP 验证保持不变。
- 原因：显式启动宿主与浏览、导入和创建皮肤无直接关系，且在两个宿主选项卡中形成冗余入口；移除单用途筛选进一步降低工具栏密度，同时保留名称、作者和 ID 搜索覆盖全部资源。
- 后果：用户不能再从换皮页单独启动 Codex 或 WorkBuddy，也不能一键只看用户皮肤；仍可通过搜索定位资源，并在明确点击“应用”时由原有安全流程准备宿主。该决定只改变 React 展示与会话筛选，不改变 core 或 Rust 宿主能力。

## ADR-005：换肤入口中文名称使用“应用换肤”

- 状态：Accepted
- 关联变更：`FEAT-SKIN-NAVIGATION-LABEL-RENAME`，`required_version = 0.2.16`
- 背景：compact 侧栏的 `/skins` 一级入口原显示“应用换皮”。用户根据实际侧栏截图明确要求改为“应用换肤”。
- 决定：中文 `navigation.skins` 固定显示“应用换肤”，英文继续使用 “App Skins”。路由 `/skins`、调色盘图标、入口顺序、活动状态与交互所有权均保持不变。
- 原因：“应用换肤”是用户确认的产品入口名称，只需在本地化展示层调整，不应为文案变化复制路由或业务状态。
- 后果：中文用户会看到新的四字入口名称；英文和所有换肤能力、数据、IPC、core 规则均不受影响。compact 侧栏需用组件回归锁定中文可见名称与原路由映射。

## ADR-006：托盘标题复用当天联合 Token 总量

- 状态：Accepted
- 关联变更：`FEAT-TRAY-DAILY-TOKEN-TOTAL`，`required_version = 0.2.16`
- 背景：用户根据 macOS 菜单栏截图要求在系统托盘图标右侧显示当天总共使用的 Token 数，并要求没有任何数据时不显示。
- 决定：托盘标题复用现有“全部”视图的联合聚合和设备当地自然日口径，纳入全部已启用本机 Agent 与已启用 WorkBuddy；当天至少存在一条用量记录时把 `total_tokens` 按十进制千进位格式化为 `K`/`M`/`B` 并固定保留两位小数，整数部分使用逗号千分位，不足 `1,000` 保留原整数；没有当天记录或联合读取失败时设置为空标题，不保留旧值。
- 决定：初次安装托盘后以及既有共享扫描节拍、扫描完成、索引清空、来源启停/移除和统一 Agent 选择变化后刷新。不得新增前端常驻查询、独立轮询、第二套聚合、远端读取或遥测。Tauri 原生标题在 macOS 可见，Linux 允许按桌面托盘实现降级，Windows 原生不支持标题并继续只显示图标。
- 原因：联合聚合是当天总量的现有唯一事实源，复用它可避免托盘数字与看板分叉；空值覆盖和事件后刷新能避免旧数字冒充当前完整事实；遵循平台原生能力可保持 Windows 托盘稳定且不引入伪造 UI。
- 后果：macOS 菜单栏会多一段随本机索引变化的紧凑数字文本；读取本地 WorkBuddy 文件也会进入刷新成本，但继续受既有扫描节拍约束。源码与单元回归不能证明真实菜单栏渲染，实际可见性留给对应最终候选 E2E。

## ADR-007：应用信息只开放固定 GitHub 仓库外链

- 状态：Accepted
- 关联变更：`FEAT-SETTINGS-GITHUB-REPOSITORY-LINK`，`required_version = 0.2.16`
- 背景：用户要求在设置的应用信息面板中加入 GitHub 图标和项目仓库链接，并在确认依赖必要性后明确授权增加 Tauri opener 依赖。
- 决定：应用信息使用 Tabler GitHub 品牌图标和带可见名称的按钮，只将固定地址 `https://github.com/ManonLoki/LokiMetis` 交给系统默认浏览器。Tauri capability 精确限制这一 URL，不允许用户输入、任意网站、文件路径或其它协议；调用失败时在当前设置页显示本地化反馈。
- 原因：系统 opener 能在 Windows、macOS 与 Linux 上保持一致的默认浏览器语义；精确 capability 比普通锚点或通用 URL 权限更能避免远程页面进入带 IPC 权限的应用 WebView，也不会形成任意导航能力。
- 后果：项目增加官方 opener 的 Rust 与前端直接依赖和一条精确 ACL；该入口只在用户点击时产生外部浏览器副作用，不建立网络客户端、后台请求、更新检查或遥测。

## ADR-008：赞助支持嵌入设置页并只使用用户提供的双收款码

- 状态：Accepted
- 关联变更：`FEAT-SETTINGS-SPONSOR-PAYMENT-CODES`，`required_version = 0.2.16`
- 背景：用户提供微信与支付宝收款码，要求加入 README 的赞助部分，并在设置中选择合适位置展示两种赞助信息。既有 GUI profile 禁用了赞助页和所有赞助媒体，当前请求构成明确的产品边界变更。
- 决定：启用赞助支持，但采用产品专属布局，把赞助区放在 `/settings` 底部，不新增 `/sponsor` 路由或 compact 侧栏入口。只逐字节复制用户提供的两张原图到 `/brand-support/sponsor/`，README 与 React 复用相同仓库文件；不复制共享模板的档位、背景、联系人或其它媒体。
- 决定：收款码只做本地静态展示，提供中英文标题、图注与替代文本，不解析、不优化、不重绘、不重编码，也不创建订单、账户、权益、自动支付或点击代理。
- 原因：设置页底部既满足用户指定位置，又不会让非核心赞助内容挤占 compact 侧栏；复用单一原始文件可避免 README 与应用内收款码漂移，静态边界不会把展示授权扩大为支付授权。
- 后果：应用 bundle 增加两张公开收款码图片，设置页内容高度增加并依靠现有滚动容器；未来禁用赞助支持时必须同时删除组件、翻译、测试与媒体。真实二维码可扫性仍需最终候选人工或 E2E 验收，本次组件测试只验证路径与可访问展示。

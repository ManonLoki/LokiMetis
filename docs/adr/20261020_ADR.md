# 2026-10-20 决策记录

## ADR-20261020-003：确认共享 Rust 配对核心与移动端薄封装路线

状态：已批准，仅记录选型，移动接入待实施。change_id：`LMDESK-PAIRING-TECH-SELECTION-001`；required_version：`0.6.0`；版本分类为`maintenance`，不提升产品版本。确认来源为用户比较Windows、macOS、Linux、iOS、Watch、Android的工程成本后，明确要求“按照你的建议 先落盘技术选型文档”。

决定沿用项目内`loki_metris_pairing`共享Rust核心；桌面直接调用，后续Android采用JNI、iOS采用C ABI薄封装。密码状态机、编码、派生与双向确认维护一份，原生应用继续拥有发现、网络、生命周期和安全存储。watchOS纳入可行性验证，其独立配对或iPhone协作模式、架构覆盖尚未确定，不据Rust目标支持等级承诺产品可用。

本条补充ADR-20261020-002的平台接入与最终技术取舍，保留其四位码、权限、限流、保存后确认和后续范围约束。比较期间提出的BoringSSL各端SDK替换路线本次不采用；macOS临时密码原语互通探针只证明该备选可互算，不代表已接入移动端，也不是最终方案的跨设备验证。HTTPS指纹路线不恢复；不引入`boring-sys`或其它新依赖。

理由是减少协议实现分叉，同时避免桌面增加BoringSSL的原生构建链；Android采用BoringSSL仍需JNI，并未消除移动原生封装成本。代价是后续维护Rust原生库的移动构建、ABI和生命周期，尤其watchOS部分目标需额外工具链工作；当前密码库的未审计与恒定时间限制继续披露。

完整平台矩阵、备选依据、历史验证边界与调整条件见[技术选型](../DEVICE_PAIRING_TECHNOLOGY.md)；线协议仍以[设备配对协议](../DEVICE_PAIRING_PROTOCOL.md)为准。本次只检查文档、链接和版本一致性，不新增代码测试、移动构建、候选或接收端功能。真实架构障碍、第三方互操作需求或安全证据触发重新评估；套件变更须共同修订兼容策略，禁止原套件名下静默替换。

## ADR-20261020-002：增加局域网设备配对阶段

状态：已批准。change_id：`LMDESK-LAN-DEVICES-001`；required_version：`0.6.0`。确认来源为本次用户请求、“采用该方案，这个配对4位即可”及最终“如果可以 走SPEAK2方案 而非Https”。

本次先交付设备导航、mDNS发现、4位配对码验证、私有保存与移除；接收端、具体数据与发送协议留待后续协商。用户已批准项目内新增mdns-sd、spake2、hkdf、sha2、chacha20poly1305，不安装全局依赖。

发现广告不授信；只有完成双向加密确认及真实原子落盘的设备进入保存列表。轻量Rust共享库拥有发送/接收双方密码状态机，Core拥有设备保存资格与稳定错误，GUI负责网络/文件驱动、后台owner和原生页面。完整协议与接收端必须满足的60秒有效期、跨IP最多5次预算等前置条件统一见[设备协议](../DEVICE_PAIRING_PROTOCOL.md)，不在此复制消息字段。

双方已协商复用`loki_metris_pairing`，固定RustCrypto spake2 =0.4.0 Ed25519变体，不以同名SPAKE2或RFC9382声明推断互通；Android/iOS未来通过JNI/C桥调用同一实现，本次不创建桥接或接收端配对功能。当前显示终端的mDNS-only广播保留`pair=off`，桌面可见但禁用配对。

4位码按用户选择保留，相比长密钥更依赖接收端限流；接收端配对尚未实现，不能据本侧源码宣称已抵抗实际在线猜测或已互通。所选SPAKE2库的未审计/恒定时间限制在技术合同披露。调整条件为未来客户端协商或真实互操作/安全问题证据；此时共同修订套件和版本，禁止静默降级为明文配对。

开发验证仅按本次相关回归实际结果报告，不创建分发候选、不签名、不发送业务数据。

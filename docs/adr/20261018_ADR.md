# 2026-10-18 决策记录

## ADR-009：增加Linux GNU双架构工具链及原生能力适配目标

change_id：`LINUX-NATIVE-TOOLCHAIN-001`；required_version：`0.3.1`。用户在当前会话明确要求添加Linux、保留完整托盘与后台热键，并同时完成Linux x64/ARM64构建打包工具链，将兼容内容更新回本项目Harness知识库。

此前目标限Windows/macOS，GPUI Skill将Linux托盘与后台热键作为未实现能力阻断。当前批准扩大本项目目标，保留其背后的安全要求：不能伪造注册成功，不能在托盘恢复不可用时隐藏主窗，不能将X11后端当作Wayland全局热键，也不能自动分配键位。批准使用现有tray-icon的KSNI特性与Linux专用ashpd/x11rb依赖；是否完成仍取决于具体实现及真实证据。

Linux构建/打包采用系统GNU工具、tar与dpkg-deb，复用现有pnpm工程入口、源码快照、资源与许可证校验；同系统跨架构不进入Tauri/xwin路线。Linux技术事实统一保存在`docs/LINUX_GPUI_TOOLCHAIN.md`，Skills与根入口渐进引用，不覆盖外部Harness源或伪造上游升级溯源锁。

管理员安装沿用系统认证，不要求发送密码；用户授权Agent执行时允许使用既有pkexec显示正常Polkit认证。添加foreign architecture、apt更新及目标开发库只为本次明确要求的交叉工具链，不获得其它系统修改或自动清理授权。

风险包括新glibc构建不能保证旧发行版兼容、桌面托盘/Portal能力随环境变化，以及交叉编译成功不能证明目标运行。包披露glibc需求，manifest保留宿主测试与目标未运行的差异；窗口、桌宠和热键运行差异继续显式追踪。

恢复依据为本次feature分支起点及其此前Windows/macOS配置；若撤销Linux目标，独立移除Linux依赖、映射和入口，保留已有源码与原始许可证，不删除系统foreign架构或已安装包。任何系统卸载与渠道发布仍需独立授权。

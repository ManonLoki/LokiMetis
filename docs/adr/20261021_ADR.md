## ADR-20261021-010：小组件使用独立HTTP只读摘要服务

状态：用户已提出并授权实现。change_id：`FEAT-WIDGET-HTTP-V1`；required_version：`0.7.0`。确认来源：本次用户反馈等待10分钟仍未更新，并要求小组件独立HTTP获取桌面数据，记录当前服务地址、下次连通更新。

背景：原Widget只读App缓存且Timeline使用never；App后台认证任务最早15分钟、实际可能更晚，无法满足独立尝试读取。桌面原发布器在TCP连接归零后休眠。

决定：扩充现有局域网监听的固定HTTP摘要入口，凭当前配对派生独立读取密钥、通过认证快照下发。手机从实际TCP对端记录服务地址，每次认证同步更新；Widget使用请求nonce绑定的ChaCha20-Poly1305拉取有界摘要。HTTP需求短暂唤醒同一权威发布器，不新增设备在线事实。Timeline申请约15分钟后再次执行，失败保留上次同步时间，切源/忘记/换地址阻止旧响应提交。

取代范围：取代ADR-20261021-003/009中Widget仅本地只读、唯一App写入、断连/45秒到期清空摘要的限制。保留手机/Watch主展示仅当前连接、长期配对密钥私有、Hook正文/图片不进入App Group、纯局域网及不保证息屏实时的约束。

影响与理由：两端需更新并连通一次，之后小组件可独立尝试；地址变化在下次认证连接更新。系统仍可推迟刷新，离线缓存不得表示当前在线。只读凭据泄露不能认证TCP或读取正文/图片，解除配对撤销读取权限；固定协议及验证边界见DEVICE_LINK_PROTOCOL。相关隔离回归与编译结果以本次提交Test说明为准，不将其视为真机自然刷新验收。

调整标准：未来改变请求格式须升级能力及协议版本；更频繁的实时/云推送属于新范围，须另行明确需求。可撤销读取配置恢复App同步路径，不删除长期配对和图片缓存。


## ADR-20261021-009：终端Token与Hooks仅属于当前连接

状态：用户已确认不缓存历史Token与状态，并明确选择“小组件仅显示短时有效数据，断开后请求清空”。change_id：`LMDESK-TERMINAL-LIVE-DISPLAY-001`；分类：feature；required_version：`0.6.2`。确认来源：用户本轮明确要求客户端不要缓存之前Token用量和状态，随后在小组件选项中明确确认短时摘要与断开清空方案。

决定：Android/iPhone/Watch停用完整快照磁盘读写并精确清理旧快照，连接失效或离开前台时清空内存展示和旧详情；保留配对、图片文件及本机展示偏好。手机到Watch的失效通知等待旧物理RPC终态后优先发出，手表撤销旧接收代次；新的完整快照才恢复数据。Widget仅读取当前连接45秒有效摘要，认证心跳续期，连接失效请求清除，过期空Timeline限制崩溃后的残留；主App永不从组件恢复数据。

取代范围：取代ADR-20261021-001/003及对应规格中离线恢复Token/Hooks、Watch完整快照持久化与长期组件缓存的要求；不改变四帧配对、共享算法、图片缓存或桌面统计权威。Widget的当前摘要共享是保持现有组件数字展示所需的临时媒介，若用户选择严格零共享状态，则应停用组件数字展示、只保留连接入口。

风险与恢复：WidgetKit调度可能延迟清屏，系统挂起时已开始的共享写入最多存活至45秒租约到期；后台不保证Watch即时收到通知，租约/系统可达变化作兜底。移动工程没有Git，本次原位修改并保留修改前文件与可审查差异；不初始化仓库。相关开发回归与SDK类型检查按本次交付报告，未据此宣称实机、候选或跨平台E2E通过。恢复旧离线展示须负责人重新确认后恢复相应持久化链路，不能通过图片命中复活Token或状态。

## ADR-20261021-008：客户端请求触发全局配对弹窗

状态：用户已确认。change_id：`LMDESK-INCOMING-PAIRING-DIALOG-001`；分类：feature；required_version：`0.6.2`。确认来源：用户要求移除设备面板发现/刷新入口，客户端尝试配对时直接显示其信息并要求输入配对码，同时输入文字可见。

决定：应用启动就提供桌面局域网服务，空账本也接收首个请求；首次启动按既有私有存储规则原子保存稳定桌面身份。设备页仅管理已配对项，配对改为应用级单个原生模态，显示未认证介绍与实际来源IP，四格输入明文显示。请求以精确连接票据提交或拒绝，取消/断开/过期释放连接；其他模态优先，真实失败在原配对模态显示，成功私有保存后关闭。

取代范围：取代ADR-20261021-004的发现列表与按钮入口，以及旧“进入设备页才联网、空账本离页停服”的生命周期；保留卡片布局、80px侧栏、密码学套件、4位码/前导零、容量/超时/地址限制、认证后信任及私有账本。不新增首帧字段、云服务或凭据权限。详细展示尺寸仍取GUI资料，完整运行合同取终端联动协议。

影响与恢复：首次运行会建立本机身份并广播，隐藏窗口也可因真实配对请求恢复显示；初始名称/ID/IP仍不代表可信在线，系统/形态仅在认证后取得。开发回归按本次交付报告，真实LAN、隐藏窗口系统表现及跨平台最终候选尚未验收。需要恢复旧入口时可回退本次提交并同步规格，已有配对账本不迁移、不删除。

## ADR-20261021-006：设备形态由终端系统上报并兼容旧端

状态：已确认并接入源码。change_id：`LMDESK-DEVICE-REPORTED-FORM-001`；required_version：`0.6.0`。确认来源为用户指出平板显示为手机后，明确要求设备提供自己的类型而非依赖名称。

决定：保留严格首条DeviceInfo，通过当前认证快照的可选能力广告协商phone/tablet形态报告；Android/iOS各自从系统分类取得值，core在当前可信租约下保存进程内形态，GUI只做平台/形态到插图的映射。具体线格式、系统来源和兼容边界见[协议](../DEVICE_LINK_PROTOCOL.md#终端自行上报设备形态)。

本条替代ADR-20261021-004中按名称提示选择插图及暂不实现类型上报的部分；四套示意图、卡片结构、未知平台中性图标与Watch从属边界继续有效。未知形态也使用中性图标，不默认成手机。

理由与代价：型号和用户名称不足以可靠区分形态；可选能力避免旧桌面因未知DeviceInfo字段拒绝新移动端。Android使用系统尺寸类别，不能保证所有折叠/窗口模式的物理类别；类型暂不持久化，重新认证前显示中性图标。报告不改变信任、IP、密钥或配对账本。

验证：本次相关开发回归分别报告，不代表平板真机、iOS完整应用或跨平台最终候选验收。恢复可回退本次扩展，保留原四字段元信息与配对凭据；未来新增形态使用独立能力协商，不恢复名称猜测。

## ADR-20261021-005：图片魔数表唯一归属 pairing，格式值域留在 core

状态：已确认并实施。change_id：`LMDESK-IMAGE-BMP-WEBP-001`；required_version：`0.6.0`。确认来源为用户当日选择“记为当日 ADR”，并确认保留 `image-webp` 直接依赖。

背景：BMP/WebP 接入后，本机图库（core `ImageFormat::from_bytes`）与设备资源传输（pairing `AssetDescriptor`）各维护一份魔数判定，且 pairing 校验另有一份 MIME 白名单；新增格式需多处同步，两侧可能对同一字节得出不同结论。core 已依赖 pairing，反向依赖会形成循环。

决定：魔数到 MIME 的识别表只在 `loki_metris_pairing::assets::sniff_image_mime` 登记一份，pairing 的识别与校验共用此表；core 的 `ImageFormat::from_bytes` 调用它并按 `mime_type()` 映射回格式。格式枚举、扩展名、展示名与 `ALL` 顺序仍由 core 唯一维护，GUI 只派生，不再手写格式列表。动态与静态 WebP 在解码像素前经 `image-webp` 读取容器头完成帧数和内存预算，`image-webp` 与 `image` 共用同一锁定版本。

影响与代价：pairing 成为图片字节识别的底层事实源，新增格式需在 pairing 表与 core 枚举两处登记；core 若有 pairing 表外的格式会识别失败而非被误判。主题与皮肤的 PNG/JPEG 范围是独立产品值域，不受本条约束。图库目录 JSON 结构保持不变。

理由：不引入新 crate 即可消除重复判定，并保证本机图库与设备传输对同一字节的判定一致。替代方案“把格式枚举下沉到 pairing 再由 core 重导出”会把图库领域类型放进传输层，暂不采用。

验证：core、pairing 与 GUI monitor 相关单元测试在 macOS 本机通过；未执行打包、实机或其它平台验证。恢复：如传输层需要与图库不同的格式范围，在 pairing 表与 core 枚举之间增加显式映射或拆分值域，并更新本条。

## ADR-20261021-003：iOS桌面与锁屏小组件复用本地展示快照

状态：范围已确认，组件和App展示投影已接入。change_id：`LMDESK-IOS-WIDGETS-001`；required_version：`0.6.0`。确认来源为用户追加“iOS支持小组件和息屏组件”；“息屏组件”按锁屏WidgetKit布局解释，常亮展示服从机型与系统支持。

iOS提供桌面小号/中号及锁屏单行/圆形/矩形组件，使用原生WidgetKit扩展，和App读取同一份App Group展示投影。成功认证解密的snapshot消息才触发投影；固定有界文件原子替换，失败保留旧数据。共享内容只有Token日期/数字/质量与Hooks四态摘要，不包含配对凭据、Hook正文或图片。Widget不链接Rust/Kotlin，也不创建局域网连接。

此选择扩展系统展示入口，不扩大网络后台能力；此前不做云推送/息屏实时保证的决定继续有效。组件明确显示缓存和同步时间，没有同步或共享失败时保留真实空态。系统时间线和App请求的刷新只表示请求，不能作为设备当前在线或通知已送达的证据。涉及敏感展示使用系统privacySensitive机制，首次解锁前允许系统遮蔽。

理由是复用App已收到的数据能控制电量和隐私边界；代价是息屏期间数据可能停留在上次同步。缓存模型与失败保留由隔离单元测试覆盖；完整App、共享容器与系统组件的运行证据另存忽略的release/，不替代物理设备App Group配置或常亮硬件验证。后续若要求实时息屏更新、Live Activities或独立组件网络，应重新核对具体范围；不以本条授权云凭据、签名或渠道发布。

## ADR-20261021-001：终端联动采用桌面数据服务与纯局域网恢复

状态：范围已批准，桌面与移动宿主已接入。change_id：`LMDESK-TERMINAL-LINK-001`；required_version：`0.6.0`。确认来源：用户明确要求发现配对、设备信息与心跳、Token总量/分量、Hooks图片缓存，说明包含普通Android/iPhone/Watch，最终明确“无后端，还是先做局域网部分吧，不做息屏推送”。不将先前的云通知选择继续作为授权范围。

数据服务放在桌面，手机主动连接，桌面在同一连接内推送更新，图片按缺失请求传输。首次发现采用手机发现桌面并报到后在桌面选中配对；四位码、共享Rust及A/B密码角色保持。该服务分工是根据用户场景作出的实施选择，不能据此承诺移动后台持续运行。

Watch采用iPhone配套路线；其状态与资源经WatchConnectivity同步。iPhone地址/心跳不能冒充Watch的IP或可达性，系统排队不表示手表已展示。独立Watch直连、云服务、APNs/FCM/厂商推送及息屏实时保证不在本次范围。

配对后业务连接采用独立随机交换、双向确认、方向密钥和严格序号，保留当前密码库未经审计及恒定时间限制。技术事实统一见[终端联动协议](../DEVICE_LINK_PROTOCOL.md)，不复制线格式。代价是两端增加原生Rust桥、缓存/恢复和服务生命周期；收益是数据权威与长期服务同属桌面，移动换IP可主动重连。

本条扩大[ADR-20261020-002](20261020_ADR.md#adr-20261020-002增加局域网设备配对阶段)中原先留待后续的接收端和业务数据范围；首次配对、私有保存、限流及其它仍有效限制继续保留。共享Rust/Android JNI/Apple C ABI取舍继续见[ADR-20261020-003](20261020_ADR.md#adr-20261020-003确认共享-rust-配对核心与移动端薄封装路线)。Linux历史授权与恢复例外仍按前一日期记录及其精确引用，不因本次联动扩大。

验证范围：桌面共享会话、在线领域、受限TCP和Token/Hooks服务与手机/Watch的原生接收、缓存和恢复分别留存运行证据；各平台与真机结果不互相替代。若后续要求息屏通知、独立Watch或直接扫描手机监听服务，重新核对对应范围与平台事实；不通过改状态文字掩盖未实现能力。

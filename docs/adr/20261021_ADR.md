# 2026-10-21 决策记录

## ADR-20261021-001：终端联动采用桌面数据服务与纯局域网恢复

状态：范围已批准、实施中。change_id：`LMDESK-TERMINAL-LINK-001`；required_version：`0.6.0`（plan）。确认来源：用户明确要求发现配对、设备信息与心跳、Token总量/分量、Hooks图片缓存，说明包含普通Android/iPhone/Watch，最终明确“无后端，还是先做局域网部分吧，不做息屏推送”。不将先前的云通知选择继续作为授权范围。

数据服务放在桌面，手机主动连接，桌面在同一连接内推送更新，图片按缺失请求传输。首次发现拟调整为手机发现桌面并报到后在桌面选中配对；四位码、共享Rust及A/B密码角色保持。该服务分工是根据用户场景作出的实施选择，不能据此承诺移动后台持续运行。

Watch采用iPhone配套路线；其状态与资源经WatchConnectivity同步。iPhone地址/心跳不能冒充Watch的IP或可达性，系统排队不表示手表已展示。独立Watch直连、云服务、APNs/FCM/厂商推送及息屏实时保证不在本次范围。

配对后业务连接采用独立随机交换、双向确认、方向密钥和严格序号，保留当前密码库未经审计及恒定时间限制。技术事实统一见[终端联动协议](../DEVICE_LINK_PROTOCOL.md)，不复制线格式。代价是两端增加原生Rust桥、缓存/恢复和服务生命周期；收益是数据权威与长期服务同属桌面，移动换IP可主动重连。

本条扩大[ADR-20261020-002](20261020_ADR.md#adr-20261020-002增加局域网设备配对阶段)中原先留待后续的接收端和业务数据范围；首次配对、私有保存、限流及其它仍有效限制继续保留。共享Rust/Android JNI/Apple C ABI取舍继续见[ADR-20261020-003](20261020_ADR.md#adr-20261020-003确认共享-rust-配对核心与移动端薄封装路线)。Linux历史授权与恢复例外仍按前一日期记录及其精确引用，不因本次联动扩大。

验证范围：当前桌面已接入共享会话、在线领域、受限TCP、Token/Hooks快照和图片分块；两端完整功能、实际配对、手机/Watch和各桌面平台仍须逐项验证。若后续要求息屏通知、独立Watch或直接扫描手机监听服务，重新核对对应范围与平台事实；不通过改状态文字掩盖未实现能力。

## 产品目标

LokiMetis 是面向 Windows、macOS 与 Linux 的 GUI-only 本机 AI 工作台：聚合本机 AI Agent 用量，管理本机 Hooks 监控与桌宠展示，并为受支持的 Codex、WorkBuddy 桌面宿主提供本机外观管理。所有公开 Agent 由一个全局复选面板启用，各业务页面只投影自身支持的子集；所有皮肤资源与偏好保留在本机，应用或停用外观只连接经过对应宿主标记验证的本机渲染页面。

本次功能的稳定 `change_id` 为 `FEAT-CODEX-SKIN-MANAGEMENT`，版本门禁给出的 `required_version` 为 `0.2.11`。

内置皮肤目录调整的稳定 `change_id` 为 `FEAT-SKIN-CATALOG-MANONLOKI-AUTHORSHIP`，版本门禁给出的 `required_version` 为 `0.2.13`。

WorkBuddy 换皮宿主的稳定 `change_id` 为 `FEAT-WORKBUDDY-SKIN-HOST`，版本门禁给出的 `required_version` 为 `0.2.13`。

统一 Agent 复选面板的稳定 `change_id` 为 `FEAT-UNIFIED-AGENT-SELECTION-PANEL`，版本门禁给出的 `required_version` 为 `0.2.13`。

监控 Hooks 信息架构与一级入口命名的稳定 `change_id` 为 `FEAT-MONITOR-HOOKS-NAVIGATION-LABELS`，版本门禁给出的 `required_version` 为 `0.2.13`。

## 当前包含

- 固定 compact 侧边栏的三个一级业务入口依次命名为「用量看板」/「Usage Dashboard」、「AI监控」/「AI Monitor」、「应用换皮」/「App Skins」；不改变 80px 侧栏几何、路由、图标、顺序或底部设置入口。
- 打包并只读展示六套内置皮肤，排除“极光静界”，且六套内置清单的作者统一为 `ManonLoki`；扫描 LokiMetis 应用数据目录中的用户皮肤，不使用数据库复制资源清单，也不改写用户皮肤自己的作者信息。
- 支持按名称搜索、只看用户资源、预览皮肤、区分内置/用户与兼容皮肤/纯主题，并显示当前所选 Codex 实例的活动皮肤。
- 设置页只展示一个 Agent 复选面板，以 core 公开目录的 Codex、Claude Code、Cursor、Grok、WorkBuddy 为固定顺序和唯一启用来源；一次选择同时驱动看板采集、Hooks、桌宠以及各页面动态选项卡，业务区域不得再复制第二套 Agent 复选。
- Hooks 目录、配置文件与写入操作放在「AI监控」下的「Hooks 设置」二级选项卡中；该页只消费统一 Agent 选择，不再提供另一组启用复选框。公共设置页继续承载统一 Agent 面板、扫描间隔与自动清理。
- 换皮页按统一启用集合与换皮能力映射动态展示 Codex、WorkBuddy 选项卡；每个选项卡独立保存当前进程中的实例选择、查询状态、活动皮肤和恢复提示，不把一个宿主的状态误用到另一个宿主。
- 支持通过文件选择和原生拖放批量导入 ZIP；导入前安全预检，重复标识自动编号，确认后才写入用户资源库。
- 支持创建标准纯主题、把兼容皮肤有损转换为新的用户纯主题、打开用户皮肤目录、导出 ZIP，以及经确认删除一个或多个未受保护的用户皮肤。
- 支持发现 macOS 与 Windows 上已验证的 Codex 或 WorkBuddy GUI 实例；Codex 可异步读取用于区分实例的有界账户资料，WorkBuddy 不读取账户资料。任何资料都不作为身份凭据或自动授权依据。Linux 明确显示当前不支持启动或注入，不伪装成功。
- 只通过回环地址上的 Chromium DevTools Protocol 连接，并按所选宿主校验页面标题、根节点与本地页面来源。用户显式选择后应用或停用皮肤；不修改 Codex、WorkBuddy 应用包、配置、会话文件、Cookie 或钥匙串。
- 对已运行但缺少调试端口的 Codex 或 WorkBuddy，先展示风险和二次确认，再只关闭并按原参数重启用户选中的已验证 GUI 主进程；WorkBuddy 使用其官方 `WORKBUDDY_REMOTE_DEBUGGING_PORT` 启动边界，不得操作 CLI、辅助进程、未知同名进程或未选择的实例。
- 记住最近一次成功应用的皮肤；当同一目标已就绪但当前无活动皮肤时，只提供用户可点击的一次性恢复入口，不自动注入或建立新的后台常驻任务。
- 保留源项目用于生成和校验纯主题的本地 Skill、模板与运行时资源，并让动态提示词使用 LokiMetis 当次真实资源路径。
- 所有用户可见文案提供简体中文与 English；浏览器预览安全降级，不声称拥有原生文件、进程或 CDP 能力。

## 当前不包含

- 不迁移源项目的更新检查、下载/安装更新、赞助页、关于页、外部网站入口、产品统计、远程日志、远程遥测或源项目品牌壳层。
- 不新增 CLI、TUI、MCP adapter、应用 updater、全局快捷键或新的网络服务。
- 不自动应用、自动恢复或在后台轮询注入皮肤；皮肤应用、停用、恢复、导入、导出、删除与进程重启都由真实用户动作触发。
- 不支持修改 Codex 应用包、绕过页面验证、连接非回环调试端点、读取认证秘密，或把账户头像/名称当作可信账号身份。
- 不承诺 Linux 上的 Codex 或 WorkBuddy 进程启动和皮肤注入；Linux 仅保持应用可编译并提供明确不可用状态，未来支持需要新的范围确认。

## 假设与约束

- 源项目当前 `master` 工作树中的换皮实现与原七套内置资源是迁移的历史参考；当前产品只保留排除“极光静界”后的六套内置皮肤，并以 LokiMetis 的 core-first、文件上限、中文注释、i18n、compact 侧栏和单一 Tauri Builder 规则为准。
- 皮肤清单、标识、资源引用、CSS 变量白名单、ZIP 边界、可删除性、转换结果与稳定错误属于平台无关领域规则，应由 `loki_metis_core` 表达并测试。文件系统、进程、CDP、对话框和原生拖放属于 GUI adapter。
- 用户皮肤只允许写入 LokiMetis 自身应用数据目录；内置皮肤与安装包 Skill 保持只读。路径、进程参数与 CDP 响应不得原样进入日志或普通错误文案。
- 导入必须限制条目数量、单项大小、总解压大小、路径穿越、链接与文件类型；任何失败不得留下半安装目录。导出只包含白名单文件。
- CDP 连接、账户探针、皮肤安装和监视任务必须按宿主与实例拥有 owner、取消路径与有界超时；离开页面或退出应用时不得遗留 detached task。
- 真实宿主验证不得误伤用户未选择的 Codex 或 WorkBuddy 实例；测试产生的用户主题和活动皮肤必须可识别并在验证结束后恢复或清理。

## 可观察成功标准

- 中英文界面中侧边栏依次出现「用量看板」/「Usage Dashboard」、「AI监控」/「AI Monitor」、「应用换皮」/「App Skins」，图标、文字、当前路由和键盘焦点符合 compact 侧栏标准，底部设置入口仍可进入。
- 换皮页能列出六套内置皮肤，不出现“极光静界”，且所有内置卡片的作者均为 `ManonLoki`；合法用户主题可被发现并保留自身作者，非法目录被拒绝并给出稳定、可操作且不泄露完整路径的错误。
- 合法 ZIP 可预检并安装；路径穿越、超限、缺少清单、非法资源引用和重复批次异常均被拒绝且不留下部分结果。重复合法标识自动另存为稳定编号。
- 用户可创建纯主题、转换兼容皮肤、打开目录、导出可重新导入的 ZIP，并删除用户皮肤；内置皮肤不能被删除或覆盖，活动皮肤删除前必须先停用或被保守拒绝。
- 在受支持宿主上，仅有一个可连接 Codex 时可直接选择；存在多个实例时不会静默选择。页面只连接回环端点且只有页面标记验证通过后才能应用皮肤。
- Agent 面板中的每个公开 Agent 只出现一次；复选成功后看板、Hooks、桌宠与换皮选项卡在同一权威快照上收敛，保存任一侧失败时不得显示部分成功。Cursor 等不支持看板或换皮的 Agent 只影响其实际支持的区域。
- 「AI监控」横向导航包含工作台、监控管理、图片管理和 Hooks 设置；进入 Hooks 设置后显示已启用 Agent 的配置目录与写入操作，公共设置页不再重复该配置区。
- Codex 与 WorkBuddy 同时启用时换皮页显示两个选项卡；关闭其中一个后只移除对应选项卡，不影响另一宿主的运行状态。WorkBuddy 页面验证不得接受 Codex 页面，反之亦然。
- 应用皮肤后目标 Codex 页面报告对应皮肤引用；停用后注入样式、脚本和监视任务被清理。需要重启时必须经过确认且只重启所选已验证 GUI。
- 最近一次成功皮肤只有在资源仍存在、目标就绪且当前无活动皮肤时出现恢复入口；忽略只影响当前会话，失败不会伪装为成功。
- 相关 core、Rust adapter 与 React 回归测试非空并通过；前端生产/测试单文件不超过 1000 行，Rust 生产/测试单文件不超过 800 行；本次涉及 Tauri 配置、资源和原生宿主能力，需完成真实开发构建与最小宿主交互验证。开发构建与单元测试不等同于发布候选验收。

## 仍待确定

- Linux Codex 与 WorkBuddy GUI 的可靠发现、启动和注入方式尚未获批，保持明确不可用。
- 后续是否增加更多内置皮肤、远程皮肤市场或皮肤同步不在本次范围。

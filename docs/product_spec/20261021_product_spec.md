- 参考源码根 Cargo 为 `0.3.15`，安装 App 实测显示 `v0.3.12`。源码可能含未提交修改，保持只读；对具体差异以实际 UI 与源码证据分别记录，不假定二者相同。
- 复用无 Tauri/WebView 依赖的领域 core。GPUI 使用原生 Rust 视图；不得以嵌入网页实现替代。

## 托盘自启与系统通知

稳定 change_id：`LMDESK-TRAY-NOTIFICATIONS-001`；分类：feature；required_version：`0.3.0`。用户于2026-10-16明确要求增加托盘开机自启，并将通知调整为每日首次突破1B、Hooks三类状态变化及换肤成功/失败。本节取代旧`LMDESK-100M-001`的每100M规则；旧事件历史保留于Git。

- 今日按当前本地民用自然日计算，复用启用来源的All canonical去重与WorkBuddy合并，不受当前页面筛选影响。只有当前日/来源、90秒内、Complete + Exact的可信快照可以触发Token事件。
- 今日总量严格大于1,000,000,000时生成每日唯一事件；恰好1B不触发，2B及更大跳跃不追加事件，下降后反弹不重复。中文正文为“恭喜您已使用{总量}的Token”，总量使用最新可信精确整数和千分位。首次可信观测已超过阈值可触发当日一次。
- 正常新日重新获得一次事件，返回已见日复用高水位。来源改变、重建索引和关闭/重新开启抑制已有消费并建基线；损坏历史保守建基线，不猜测已经通知的事件。保留32个日界。
- 私有`usage-notification-state.json`沿用256KiB上限与先入队落盘、再预约落盘的发送顺序。策略版本升级为2，稳定ID使用m2；合法旧100M账本只迁移可信日界去重事实，取消旧待发、预约和重试。旧第10档不能证明严格超过1B，由新的可信总量决定基线；第11档及以上可确认已超过。旧m1回执不能重排新事件。
- Token确定失败保持同ID，初次外最多自动重试3次，退避30/120/600秒；耗尽等待主动重试。超时/崩溃预约保持Unknown，不盲目重投；系统历史匹配才确认，否则手动重试提示可能重复。
- Hooks仅消费启用门禁通过、生命周期状态机已接受的状态变化：进入实际询问或错误时通知；工作正常完成时通知结束。中文正文固定为“{Agent}需要您决策”“{Agent}出错了”“{Agent}已完成”，Agent使用公开目录显示名，名称与状态之间不增加空格或标点。取消、中断、单纯关闭会话、普通工具执行前、重复状态、启动空闲、超时回收及停止后的会话释放不冒充完成或询问。工具自身保存前态，不依赖可能被其它工具覆盖的桌宠槽位；可恢复工具错误不退休父轮次，随后真正完成仍可通知结束。子Agent、工具调用与MCP澄清按独立归属处理；无关工具或压缩不能解除其它询问。各原生协议的终态依据和信息不足边界见[Hooks协议依据](../HOOKS_PROTOCOLS.md)。
- Codex/WorkBuddy皮肤实际应用成功或失败均通知。重启/外观确认是中间步骤，取消不是失败；资源创建、导入导出和停用不冒充更换成功。终态观察在应用后台owner内执行，离页不吞掉已提交事务的真实成功/失败；正文只含公开宿主名称和结果，错误详情留在应用内。
- 三类通知共用已确认本地总开关、系统权限、原生owner和单在途提交槽。启动只读查询权限，授权仍来自用户主动开启或重试。Hooks/换肤使用至多128项、60秒有效的内存邮箱，关闭/权限暂停/退出清除，暂停期间不积压、不跨重启重放，不因今日用量读取失败而停用它们。Token独立持久去重，不受瞬时队列影响。
- macOS原生delegate识别m1/m2和瞬时a1通知，保持前台banner/list静音和点击恢复；Windows沿用本产品AUMID及Activated/Failed回调。Token的API Accepted与真实横幅送达仍是不同事实。
- 摘要沿用独立单worker，通知开启或桌宠可见时启动/每30秒刷新；扫描提交、来源变更、激活/唤醒和日界合并触发。主线程轮询不查询磁盘或OS，退出停止派发并保存已接受Token回执。

本次开发完成条件：相关非空领域、存储、通知、托盘、Hooks监听和换肤终态回归通过，并创建可审查本地提交。真实OS横幅/点击、实际登录启动、Windows完整宿主及正式候选验收仍单独取证；本次请求不扩展为打包、发布或推送。

## 局域网设备发现与配对

稳定change_id：`LMDESK-LAN-DEVICES-001`；分类：feature；required_version：`0.6.0`。用户要求增加设备菜单和页面，通过mDNS发现局域网设备，配对成功才保存；2026-10-20阶段先完成桌面发现/配对/保存与移除，并明确将配对码改为4位。

- 增加“设备”导航，区分已配对设备与发现候选，显示发现中、空列表、近期发现/未发现、真实错误和提交结果；保持80px侧栏、原生语义按钮、双语和主题。
- 用户进入页面或主动发现才浏览兼容LokiMetris接收端，不把所有mDNS广告都当作可配对设备。广播中`pair=off`或缺省仍显示设备并说明尚未启用配对，只有`pair=1`启用配对入口。发现候选不持久化，单轮12秒、短时有效；离页或隐藏取消临时活动，已接受的原子文件提交仍真实收尾。
- 4位ASCII码保留前导零，桌面与未来移动端复用轻量Rust配对核心，基于SPAKE2、HKDF-SHA256和ChaCha20Poly1305完成双向身份/密钥确认；未经认证最终回执不能产生可保存证明，落盘失败不能显示保存成功。不自动重试密码交换。
- 设备列表与配对凭据只写本产品独立私有账本，成功原子替换后才更新内存。损坏/不安全权限/链接/无效字段失败关闭，不以空列表覆盖。已保存名称、身份及凭据不受新广告覆盖。移除需确认，仅移除本机信任。
- 接收端必须使用短时随机码、跨连接/IP共享最多5次总尝试预算和成功失效；此约束待未来接收端实现，本次不声称单侧限流或跨设备互通已完成。完整消息格式、地址/容量/超时/取消/权限合同以[设备协议](../DEVICE_PAIRING_PROTOCOL.md)为唯一技术事实源。

首次配对的四位码、身份与私有保存约束继续生效；2026-10-21新增的接收端及业务同步范围以下节为准，既有源码或夹具通过不代表新增范围完成。

开发完成条件：领域成功/错码/元数据篡改/重放/校验，真实TCP握手与断连/超限/超时，私有存储恢复与失败保留，原生导航/按钮所有权/模态/键盘和双语相关回归通过。没有接收端时显示真实空态；单元夹具和macOS结果不替代真实局域网、Windows/Linux或最终候选验收。


## 手机与Watch局域网联动

稳定change_id：`LMDESK-TERMINAL-LINK-001`；分类：feature；required_version：`0.6.0`（版本门禁plan；本周期功能锁已开启）。范围确认来自用户的五项联动目标、普通Android/iPhone/Watch及息屏场景说明，以及最终“无后端，还是先做局域网部分吧，不做息屏推送”。状态：实施中；不得把共享库、测试夹具或协议文档当作两端已接通。

- 桌面拥有Token/Hooks权威数据并提供局域网服务，手机主动发现并建立连接；手机报到后在桌面设备页显示待配对终端。保持四位码及共享Rust密码状态机，TCP连接方向不改变桌面A/终端B的密码角色。Android/iOS原生桥和终端应用接入也属于本目标。
- 已配对设备以稳定应用UUID和保存凭据认证。设备名称、平台及应用版本来自认证会话；当前IP只采用实际socket对端地址。IP或名称变化不建立新设备身份，也不据广告改写信任。
- 运行且网络可达时实时推送；心跳只证明应用可通信，超时或后台挂起显示暂不可达与最后通信时间。配对关系、接收端最新快照及图片缓存保留；恢复或网络变化后重新发现、认证并补齐最新状态，不承诺息屏实时更新。
- Token默认使用当前本地自然日，发送所有启用来源的总量和实际支持统计的各Agent分量，沿用现有去重、WorkBuddy合并、时间与数据质量。缺失或读取失败不能冒充可信零，Cursor没有Token来源时不虚构分量。不把“当前窗口合计”称为全历史总量。
- Hooks发送经过现有状态机接受的Agent/槽位/行为及图片引用，不发送原始会话、prompt或工具载荷。图片以内容哈希清单按缺失请求传输，校验后原子写入终端应用私有目录；已有同哈希资源直接复用，缺失或损坏可补取。只缓存实际引用资源，不自动复制整个图库或写用户公共目录。
- Apple Watch先通过iPhone配套通信同步当前状态和所需图片，保留独立最近同步信息。iPhone的TCP心跳/IP不能冒充Watch在线/IP；系统后台传输已排队不等于手表已经展示。独立Watch直连桌面和Wear OS不在本轮已选路径。
- 配对确认密钥不能直接发送业务数据。配对后的每次连接采用独立随机交换、方向密钥和严格序号，认证失败/重放关闭会话；移除信任后撤销相应活动连接，旧连接不能覆盖重新认证后的状态。技术合同以[终端联动协议](../DEVICE_LINK_PROTOCOL.md)为准。

不包含：APNs/FCM/国内厂商推送、云后端、外网穿透、中继账号、息屏保活承诺、独立Watch网络方案、远端管理/命令执行、发布、签名或渠道分发。用户曾选择息屏重要通知，随后明确撤回，本次不保留该范围。

桌面数据服务阶段独立change_id：`LMDESK-LAN-DESKTOP-SERVICE-001`；required_version：`0.6.0`。已完成桌面接线及相关自动化回归；主目标的移动端与实物互通仍未完成。

完成标准：两端真实四位码配对与保存、认证元信息/IP、心跳断开及重连换IP、同窗Token总量与分量、Hooks状态和图片首次传输/缓存命中/缺图补取可观察；相关最高风险失败回归通过。Android、iOS、Watch以及桌面各宿主按实际证据分别报告，环回夹具不证明实物联动完成。


### 移动端菜单分工

用户于同日明确要求配对归设备管理、终端名称等收进设置、展示独立菜单。change_id：`LMDESK-TERMINAL-MENUS-001`；required_version：`0.6.0`。

- 移动端提供独立“展示”“设备管理”“设置”入口，默认进入展示；未收到真实数据时保留未连接空态，并提供前往设备管理的按钮。
- 展示只承载接收到的Token与Hooks图文；设备管理承载发现、配对及已连接设备操作。尚未完成的配对不因调整菜单标为可用。
- 设备名称编辑、设备ID等本机信息集中在设置；名称只在明确保存后提交，保存不启动/停止网络，下一次连接使用新名称。
- 切换菜单保留草稿及当前连接意图，不创建或销毁网络owner；后台行为仍只由应用生命周期处理。桌面原“设备”入口同步命名为“设备管理”。

本条只调整联动功能的信息组织，不改变协议、信任、图片缓存或已确认的纯局域网范围。相关决定见[ADR-20261021-002](../adr/20261021_ADR.md#adr-20261021-002移动端展示设备管理与设置分离)。

### iOS 桌面与锁屏小组件

用户追加要求“iOS支持小组件和息屏组件”。change_id：`LMDESK-IOS-WIDGETS-001`；required_version：`0.6.0`。息屏组件按锁屏 WidgetKit 组件实施；支持机型上的常亮显示由系统管理，不改变此前不做息屏推送的边界。

- 桌面提供小号、中号，锁屏提供单行、圆形、矩形布局；展示真实同步的 Token 总量、各 Agent 分量及 Hooks 状态摘要，不保存 Hook 正文、图片或配对秘密到组件共享文件。
- App 与组件使用同一 App Group 容器中的有界展示快照；只有经会话解密并通过展示解析的数据才能写入。新完整快照成功后原子覆盖，失败保留原快照；组件只读本地，不建立局域网长连接。
- 组件始终注明缓存/最近同步，使用桌面快照的日期与质量，不把昨天数据标作今日，不把历史 Hook 状态标作当前在线。未同步、文件损坏或共享容器不可用时显示真实空态。
- App 收到新快照后请求 WidgetKit 刷新，实际时机由系统调度。系统首次解锁前或用户选择隐藏敏感信息时允许系统遮蔽；不承诺息屏实时更新、强制常亮或通知送达。
- 写入范围仅为共享容器内固定快照文件；主 App 是唯一写入者，组件只读。临时文件同目录原子替换，解析失败与写入失败不能覆盖有效旧数据；测试使用隔离临时目录验证这些行为。

小组件不等同移动网络接入完成；真实手机联动及组件实机添加仍分别核对。相关长期边界见[ADR-20261021-003](../adr/20261021_ADR.md#adr-20261021-003ios桌面与锁屏小组件复用本地展示快照)。

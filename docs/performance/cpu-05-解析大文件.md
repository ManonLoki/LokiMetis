# CPU-05 解析大文件：切行、借用字符串、增量读

应用要读很多 JSONL 日志（Codex、Claude、WorkBuddy 的对话记录），一读就是几十到上百 MB。
这类代码的优化点很固定。

## 1. 切行：一次找一整行，别逐字节追加

原来逐字节判断换行、逐字节往行缓冲里追加。改成：先在已读到的缓冲区里**找换行符的位置**，找到后**整段复制**。
同样 19,981,371 字节的合成输入，旧约 0.1506 秒、新约 0.0421 秒（约 3.6 倍，只含切行，不含 JSON 解析）。

保留的边界：
- 预读不能越过本轮"冻结的文件长度"；
- 单行最多 1 MiB，超长行跳过但要计入警告；
- 末尾没有换行的半行不提交；
- 读到的错误要原样传播（标准库的 `read_until` 会悄悄重试 `Interrupted`，会改变错误行为，所以用了更底层的 `fill_buf`）。

## 2. 借用字符串，别每行都 new String

解析每一行都要先拿出 `sessionId`、`cwd`、`messageId`、`model`。大多数行最后会被忽略，
但原来每行都为这几个字段各分配一个 `String`。

改成 `Cow<str>`：没有转义字符的直接**借用这一行的内存**，有转义才分配。
容易踩的坑：`Option<Cow<str>>` 加了 `borrow` 标注**并不保证真的借用**，要写测试断言它是 `Borrowed` 而不是 `Owned`。

## 3. 增量读：只读追加的部分，但要证明"已读到哪"

只比较文件大小和修改时间，不能证明可以跳过读取：上次可能被取消，只读了前半段。
跳过前还要检查"已解析偏移 + 尾部未闭合字节 == 观察到的文件大小"。
坏行警告属于当前这一代来源，不能因为本轮没重读就清零。

## 4. 解析不动的文件，直接复用结果

文件没变就别再解析，见 [CPU-02](cpu-02-没变就别重读.md)。这是收益最大的一招。

## 5. 先整理再并行 / 别在 canonical 之前裁剪

想只算"今天"的数据时，不能在去重之前就按日期过滤原始行：
跨天的重复调用和冲突需要先去重才能判定。要保留完整去重语义，再减少展示性分配。

# UI-04 测卡顿时别被"后台窗口"骗了

## 现象

自动化工具说"应用已经在前台、窗口已经提升（raise）"，按钮点了业务状态也变了，
但截图和辅助功能树里还是旧画面，必须 resize 一下才刷新。看起来像"窗口冻住了"。

## 真相

在该次 macOS 测量中，窗口遮挡状态导致帧订阅暂停；“不是前台应用”本身不能证明窗口已被遮挡或完全停止绘制。
resize 会强制绘制，所以一 resize 就"恢复"。这是**测量环境的问题，不是产品卡死**。

## 怎么避免

- **测之前先确认真正的前台进程 PID。** 工具说"绑定了应用"、`AXRaise`、key window，都不证明它在前台。
- 在前台身份是别的应用（比如 Finder）时，通过 Finder 打开同一个已运行的应用，让它真正成为前台，再测。
- 记录实验时把"实际前台是谁、窗口是否可见"写进条件。
- 测主题卡顿别用离屏的旧截图。

## 另一类误判：文件名

我们有一份资源文件叫 `gpui-front-...`，但四个端点的真实前台全是 Finder。
**不要相信文件名**，要相信记录下来的前台身份。

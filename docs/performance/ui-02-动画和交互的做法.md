# UI-02 动画和交互：在绘制阶段做变换

## 按钮按压缩放

按钮按下要有 `translateY(1px) scale(0.985)` 的 200 毫秒动画。

### 笨办法 vs 好办法

- 笨办法：改布局尺寸。会挤动旁边的兄弟元素，字形和 SVG 也要重新栅格化。
- 好办法：**布局不变，只在绘制阶段对最终图元做几何变换**。保留字形的 `font_size` 和缩放系数、SVG 图集键，
  只变换图元位置和采样矩阵。文字、图标、背景、边框一起变换，命中区域也用同一个映射。

### 要点

- 变换以原 border-box 的中心为准；
- 缓存和延迟绘制需要保存变换作用域，而场景回放时不能再次应用变换；
- 祖先的裁切区域保持原屏幕区域，不能跟着子按钮变大；
- 加载遮罩也保留原栅格尺寸，不要因为动画每帧的微小尺寸变化而触发重新栅格化和图集上传；
- 鼠标和键盘的"取消"状态要分别保存，另一种输入或系统重复按键不能复活旧的 release。

## 菜单

原生菜单动作表以前每次重建都追加克隆，即使动作值相同。修成：按动作的完整值比较，复用稳定索引，只给第一次出现的值加槽位。

- 不能只按类型去重，参数不同的同类动作必须独立；
- 菜单项"显式禁用"和"动态可用"要分开保存；
- 调用业务回调前要先释放平台锁，否则回调里再加锁会死锁。

## 标题、滑块这类小事

小事叠起来也会卡：

- 每次 render 都调原生 setter（NSString、NSWindow.setTitle）；
- 每次渲染都对控件赋同一个值触发通知；
- 把"用户正在拖动的值"和"已经保存确认的值"搞混，导致即时绘制用旧偏好把输入覆盖。

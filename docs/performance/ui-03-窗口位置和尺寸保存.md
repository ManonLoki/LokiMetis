# UI-03 窗口位置和尺寸：防抖、回执和退出保护

窗口一拖动，系统会连续发来很多 bounds 通知。如果每次都写文件，就是 IO 风暴；如果处理不好，又会丢位置。

## 防抖要做对

- 位置先按屏幕缩放换算成**物理像素**再比较；
- **不同位置静止满 200 毫秒才提交**；
- **相同目标不重置计时**，否则连续的同值通知会让保存永远不到期；
- 队列要分别记住 `desired`（想要的）、`in-flight`（正在写的）和`最近成功`的回执。

### 几个必须保留的时序

| 情况 | 必须怎么办 |
|---|---|
| 已保存 A；B 还没被接受；又回到 A | 可以取消还没发生的 B |
| 已保存 A；B 已经在写；又回到 A | 要保留"恢复 A"的意图，不能因为当前快照是 A 就取消 |
| B 已成功；旧展示快照 A 晚到；随后回 A | 不能吞掉真实的 B→A 恢复写入 |
| 写入失败且又来了更新的位置 | 旧失败不能丢掉较新的意图 |

"发起成功"不等于"磁盘保存成功"，要等正式回执。

## 退出时保护最终位置

正常退出时，有个屏障保存"最终位置"。晚到的后台写入如果想写旧的 B，应该改用最终的 A。
关键是：**必须在拿到修改锁之后才读屏障**，锁前读会留下竞态。

不要把各个等待时间相加然后承诺"退出最多 6 秒"；已经接受的阻塞写入可能继续等锁。

## 动画还没结束时别保存中间值

实机出现过：窗口宽度 961 被保存成了缩放动画中间的 1383。
静默 250 毫秒只负责合并，不能证明动画完成。要用系统给的目标矩形和实际外框比较（容差半个物理像素），
未知目标时保持保护。最大化时迁屏只映射最后可信的"普通"锚点，不能拿最大化外框当普通尺寸。

## 辅助窗口

无边框配置窗在 AppKit 里也会返回 `isZoomed=true`，不能照搬主窗口的"必须非 zoom"保护。
读回位置要有界等待，时间到仍不匹配就记失败，不放宽容差。

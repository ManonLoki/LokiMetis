# CPU-04 动画每帧重复的计算要缓存

## 问题

切换主题要播 300 毫秒的动画，期间阴影、描边的颜色每一帧都在变。
但**阴影的"圆角挖空形状"只取决于尺寸、缩放和半径**，跟颜色无关。
原来的实现每一帧都把整张阴影纹理的覆盖率重新算一遍。

## 怎么发现的

切换主题时对应用采样 12 秒，主线程上 `ShadowGeometry::render` 一个函数就占了 348 个采样点（约 6.4%）。
对比静态设置页采样，这个函数是 0。说明热点只在动画期间出现。

## 怎么修的

把"只跟尺寸有关"的部分算一次存起来（几何计划），"跟颜色有关"的部分每帧只重算那一小段：

- **阴影**：按行把相邻、数值完全相同的覆盖率压缩成连段，颜色变化只重算高斯轴并重新着色。
  尺寸、缩放、半径变了才重建计划；隐藏、离屏、卸载时丢掉。
- **描边（rim）**：每个像素的贡献按原顺序记下来，重着色时仍按原顺序逐次累加。
- **动画端点颜色**：五组端点的颜色转换结果缓存，输入（明暗、悬停、强调色）不变就复用，
  但**每帧仍按原顺序调用 setter 和采样**。
- **透明阴影**：透明像素的 RGB 仍要写出，但可以批量填充，跳过全零的纵向投影。

## 效果

用标准库写的微基准，提取未改动的 CPU 公式，交替跑新旧各 8 轮，计时外先比对像素完全一致：

| 项目 | 旧每帧 | 新每帧 |
|---|---|---|
| 阴影（长卡片 2×） | 3.044 ms | 0.885 ms |
| 描边 | 2.655 ms | 0.046 ms |
| 透明阴影批量填充（-O3） | 0.512 s/批 | 0.183 s/批（约 2.8 倍） |

这些只是"CPU 栅格化这一小段"的收益，**不含 GPU 上传和整帧布局**，不能乘到整个应用的帧率上。

## 别踩的坑（非常重要）

- **浮点数不能随便"代数化"。** 把"累加 N 次"改成"乘以 N"看着等价，实际会差一个舍入：
  有一个真实反例，原始累加得到 127，改成乘法得到 128。我们在测试里保留了这个"错误写法"作为反例。
- **透明不等于全零。** 旧算法里透明像素的 RGB 也进入最终字节，不能因为 alpha 是 0 就写 0。
- **缓存要有清理。** 隐藏、空区域、卸载时必须释放，否则图集里会留旧图。
- **缓存的键要含原始位值**（连正负零都要区分），不然尺寸变了会误用旧计划。
- **缓存会占一点内存。** 长卡片 2× 约 63～74 KB，要写清楚，不能说"零成本"。

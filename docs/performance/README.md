# 性能调优经验手册

这套文档用人话讲清楚：这个应用哪里曾经慢、哪里曾经费内存、我们怎么发现的、怎么修的、效果到底怎么样、哪些路走不通。
每篇只讲一件事，按维度分类，想查什么直接点开对应那一篇。

> 更严谨的逐案例证据（命令、构建指纹、测试名、原始数据位置）在 [../PERFORMANCE_OPTIMIZATION.md](../PERFORMANCE_OPTIMIZATION.md)。
> 本目录是"给人读的版本"：先说结论，再说为什么。两边冲突时以那份带证据的文档为准。

## 先记住五句话

1. **先量，再动手。** 没有采样和对照，"我觉得这里慢"十有八九是错的。
2. **空闲的程序应该真的空闲。** 每秒醒几十次的定时器，加起来就是持续耗电和占 CPU。
3. **没变就别重算。** 数据没变，就别重读、重解析、重聚合、重绘制。但"没变"必须有可靠的判据。
4. **内存要分清是谁的。** 应用自己的堆、系统映射的文件、显存纹理，是三回事，混着看会被误导。
5. **每个优化都要能被证明有效，也要能被证明没改坏行为。** 我们撤销过两个"看起来有用"的改动，因为实测没用甚至更糟。

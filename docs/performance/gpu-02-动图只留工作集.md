# GPU-02 动图只留当前要用的帧

## 问题

一张 120 帧的动图，如果把已经播过的每一帧都留在显存里，播一圈就把 120 帧全占满了。
更糟的是，同一个动图在两个窗口里"错相"播放，每个窗口各留一份。

## 怎么想

关键问题是：**此刻真正需要显存里有哪几帧？** 答案是"每个播放器最后一次成功绘制出来的那一帧"，
同一窗口里多个位置取并集。

## 怎么修的

- 每个播放器记录"最后一次成功 paint 的实际图片 ID 和帧号"，同窗口取并集；
- 下一次成功绘制替换旧记录；**失败的绘制不要提前撤销旧帧**；
- 缓存场景（cached view）没有回调时，继续保留它原来那一帧；
- 换帧时只清旧帧的 key；位置卸载或孤立的 paint 必须刷新场景；
- 收尾任务每窗口合并一次，执行前再检查一遍并集，要能处理 A→B→A、同帧多位置、错相播放。

## 效果

旧策略下，一个 12 帧 APNG 暖机后会累计 5 帧；新策略下，单位置每次边界只保留 1 帧，错相双位置保持 2 帧。
图库的 120 帧动图实测：旧约 1.03 GB 图形内存，新约 29 MB（见 GPU-01 的条件说明）。

## 别踩的坑

- **有界的是"活跃的逻辑帧集合"，不是瞬时显存硬上限。** GPU 慢的时候可能暂留几个已退役区域（见 GPU-01）。
- **内存下降 ≠ CPU 改善。** 工作集小了，每帧可能要重新上传，这个成本要单独测。
- **只对 macOS 播放器启用**。Windows 没验证过。

## WorkBuddy 国内版/国际版双根修复（BUG-WORKBUDDY-INTERNATIONAL-DUAL-ROOT-20260921）

**问题**：统计与 Hooks 都只认固定根 `~/.workbuddy`，国际版 `~/.workbuddy-ai` 完全不可见。
本机实测确认：国际版有 17 个 JSONL / 919 条可用 usage 行 / 1.196 亿 Token 被漏统计；
其 `settings.json` 也没有 LokiMetis 写入的 hooks。

**用户确认口径**（三选一均取推荐项）：
- 统计口径：合并为一个来源，仍只有一个「WorkBuddy」选项卡与开关。
- Hooks 范围：两个固定根都写入。
- 交付范围：改代码 + 跑相关测试，按 bug-fix 升 Patch（不做构建/发布）。

**版本**：`0.3.7` → `0.3.8`（`version_gate.py apply --kind bug-fix`），Cargo.lock 已同步。

### 关键教训 / 可复用套路

1. **行数硬门禁**：`check_file_line_limits.py` 对 Rust 是 400 行 REVIEW / 800 行 ERROR。
   超限时按仓库既有约定拆成 `<module>/mod.rs` 目录结构（仓库已有 48 处）。
   本次 `monitor/store.rs` → `monitor/store/{mod.rs,locations.rs,tests.rs,locations_tests.rs}`。
   拆完必须同步修：
   - `#[path = "store_tests.rs"] mod tests;` → `mod tests;`（自动解析到 `store/tests.rs`）
   - 测试里的 `include_str!("store.rs")` → `include_str!("mod.rs")`，
     `include_str!("commands.rs")` → `include_str!("../commands.rs")`
   - 被移动的私有函数若被子模块使用，需改成 `pub(super)`
   - 子模块测试文件要重新 import 父模块用到的 core 符号（如 `ai_tool_name`）
2. **Bash 的 `grep`/`rg` 在本沙箱不可靠**（常返回假空结果），一律用 IDE 内置 Grep 工具或 Python。
3. 验证脚本三件套：`check_file_line_limits.py`、`check_rust_chinese_comments.py`、`check_core_first.py`，
   都在 `.agents/skills/desktop-implement-change/scripts/`。

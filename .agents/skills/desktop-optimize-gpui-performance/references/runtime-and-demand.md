# 运行时、任务与重绘需求

GPUI 原生 loop 留在同步主线程。只有业务确需异步 I/O 才由适配器应用服务拥有一个 runtime；render/handler 不做同步文件、网络、解码、数据库或外部进程工作。CPU 重任务与异步任务分别限流，不能把 started blocking 当成可 abort 的 future。

查询、写入、扫描、原生服务分开拥有队列和关闭路径。对可替换查询可使用 active + latest pending，写入则按业务语义顺序执行，不能一律丢弃。generation/revision/owner 过滤迟到结果；取消后合作收尾，不能让旧响应覆盖新视图。全局容量应覆盖 active、正在关闭及异常转交的任务，超时保留需要回收的句柄，不用 detached 掩盖泄漏。

窗口事件、拖动与偏好写入合并最后意图。同一物理像素或同值不重复提交；OS 成功回执决定已提交状态。退出最终快照与普通写入共用正确同步边界，防止迟到事件覆盖。UI 等待取消不能阻塞主循环；不可取消的最终退出按真实 owned 资源刷新。

共享设置首次读取/保存可能由任一消费者触发。加载权威快照后，仍须发布其它消费者需要的启用集合或目录投影；缓存命中和同位置noop不能吞掉首次发布或磁盘事实变化。普通同值移动也不能重复触发Hooks修复等昂贵副作用，应分别判断权威数据是否改变、消费者是否已初始化。本项目回归见`loki_metris_service/src/usage_service/hooks_startup_tests.rs`，实际命令到状态机的验证范围见[Linux能力证据索引](../../../../docs/LINUX_GPUI_TOOLCHAIN.md#已验证能力与证据索引)。

只在可观察状态改变时 notify，静态/已结束动画不轮询。按真实页面/窗口消费者决定查询和动画调度；失焦、最小化、隐藏、遮挡是不同状态，不能简单等同。timer 按真实 elapsed 校正，迟到不累积固定步长漂移。观察需求来源，避免一个全局周期让所有页面重渲染。

底层 display-link 可能仍按刷新率回调，即使补丁已减少主线程派送；“无需求不派送”不能写成“完全没有空闲唤醒”。只在应用机制不足且有测量依据时改后端，具体兼容规约交依赖 Skill。

日志采用有界后台队列、结构化字段与字段限长；饱和时可丢诊断，业务结果不依赖日志队列。端侧只装一个 subscriber；最终退出刷新，不能让格式化/文件 sink 占用 render。

## 从视觉参考建立系统

不要逐像素复制一张参考图。先提取可复用规则：

1. 确定皮肤的视觉主题、目标用户和工作密度。
2. 建立颜色角色，而非只列色值：背景、面板、浮层、强调、危险、成功、主文本、弱文本和分隔线。
3. 建立表面层级：应用背景、侧栏、内容区、编辑器、菜单/弹层、装饰层。
4. 建立固定尺度：侧栏最小宽度、编辑器最大宽度、工具按钮尺寸、边框宽度、圆角和间距序列。
5. 为文字定义正文、标签、标题、代码和数字层级；不要按视口宽度缩放字体。
6. 动效只表达状态或层级，持续装饰动效必须响应 `prefers-reduced-motion`。

将设计令牌集中在 `html.codex-dream-skin` 的 CSS 变量中。明暗模式可以重写令牌，不要复制整套页面规则。

## 图片与内容适配

- 主图应能在 `cover` 裁切下保留主体；资料图和列表图优先使用 `contain`。
- 为图片容器设置稳定的 `aspect-ratio`、最小/最大尺寸和溢出规则。
- 纯主题不得创建宽屏装饰窗；旧六文件皮肤的扩展装饰不得遮挡编辑器、会话滚动区或设置页面，窄屏应隐藏或转为背景层。
- 使用渐变遮罩保证文本对比度时，仍要检查浅色与深色素材。
- 不把参考图中的品牌、人物或商标默认带入新皮肤；只有用户提供或明确授权时使用。
- 不把图片编码直接硬写进 CSS 模板；由宿主转换为 Blob URL 或本地相对资源。

## 页面覆盖矩阵

至少记录以下矩阵。若某项不适用，明确写“不适用”而非省略：

| 场景 | 必查内容 |
| --- | --- |
| 首页 | 标题、项目选择、建议卡、编辑器、横幅、首屏裁切 |
| 普通会话 | 用户/助手消息、代码块、列表、工具调用、编辑器、滚动到底部 |
| 长会话 | 虚拟滚动、固定元素、长代码、横向滚动、底部编辑器 |
| 空/错误状态 | 空列表、加载、离线、警告、错误、重试动作 |
| 拉取请求 | 列表、搜索、状态筛选、空/错误状态、详情分栏、标签页、代码审查 |
| 站点 | 空状态、站点卡片、缩略图、筛选、访问状态、创建动作、站点设置 |
| 已安排 | 建议、列表、历史、暂停状态、详情分栏、编辑表单、插件来源 |
| 插件 | 搜索、浏览/管理标签、插件卡片、开关、市场、空/错误状态、详情 |
| 设置 | 顶部应用菜单、主内容表面、分组卡片、返回控件、表单、单选/复选/开关、菜单、对话框、装饰遮挡 |
| 浅色/深色 | 文本、图标、边界、焦点、selection、代码高亮 |
| 窄/宽窗口 | 900 px 以下、常规桌面、1450 px 以上；无重叠和横向溢出 |
| 缩放 | 80%、100%、125% 或平台可用的等价缩放 |
| 减少动态效果 | 所有持续动画停止或显著减弱 |

## 自动与静态检查

LokiMetis六文件格式先执行 `node scripts/validate_skin.mjs` 和 `node scripts/audit_component_map.mjs`。此外检查：

- CSS 中所有宿主覆盖均受根 class 限定。
- JavaScript 不含 `eval`、远程脚本、网络请求或本机绝对路径。
- MutationObserver 使用节流；周期扫描不低于合理间隔。
- 用户配置文本通过 `textContent` 或 JSON 安全写入。
- CSS 变量都有默认值或由注入脚本保证赋值。
- `:has()`、容器查询或较新特性有符合当前 Codex Chromium 版本的依据；不确定时提供降级。
- 自建按钮具有 type、可访问名称、键盘行为和可见焦点。
- CSS 宿主选择器与注入脚本 `HOST_SELECTORS` 中的每个选择器原子均已登记到 `component-map.yaml`。
- 首页、会话、拉取请求、站点、已安排、插件、设置与 other 的页面状态、预览入口和检查记录数量一致。

静态检查只能证明结构合理，不能证明 Codex 当前 DOM 匹配。

## 真实 Codex 验证

1. 在测试会话或可恢复环境启动目标 Codex 版本。
2. 注入一次，记录样式节点、自建根节点、全局状态和根 class 数量。
3. 逐项浏览页面覆盖矩阵，检查控制台错误与布局。
4. 注入第二次，确认没有重复装饰、重复监听或明显闪烁。
5. 切换明暗模式、调整窗口宽度、滚动长会话并打开弹层。
6. 调用 `window.__CODEX_DREAM_SKIN_STATE__.cleanup()` 或宿主卸载入口。
7. 确认样式、自建 DOM、根状态、临时 class 和事件效果均消失。
8. 重新注入，确认卸载后仍可正常启用。

允许使用截图作视觉证据，但还应检查 DOM 数量、控制台和可交互状态。截图非空不等于交互可用。

## DOM 漂移诊断

皮肤突然失效时按层定位：

1. 确认注入脚本执行且六个占位符已替换。
2. 确认 `html.codex-dream-skin`、样式节点和全局状态存在。
3. 确认宿主页 URL 与 Codex 页面校验仍成立。
4. 检查 A 级语义锚点是否变化，再检查 B 级具名 class。
5. 检查页面分类是否误判，例如设置页仍残留会话 DOM。
6. 检查 CSS 是否命中但被更高优先级、shadow DOM、portal 或内联样式覆盖。
7. 只修复失效层，避免为了一个区域重写整套注入逻辑。

属性名只证明锚点稳定，不证明组件粒度。对前缀 ID、分区 `data-*` 和布局容器施加背景、圆角或阴影前，必须在实机报告中核对标签、角色、几何尺寸与视口占比；设计预览必须复现已观察到的父子层级，不能为了方便把分区 ID 挂到卡片上。

为漂移修复记录旧选择器、新选择器、验证页面和回退策略。不要删除仍服务于受支持旧版本的回退，除非确认它会误匹配。

## 交付记录

交付说明至少包含：

- 皮肤目录或 ZIP 路径、ID、名称和作者。
- 使用的运行格式与宿主要求。
- 主要设计令牌和图片来源。
- 新增或依赖的 C/D 级脆弱选择器。

- 静态校验命令及结果。

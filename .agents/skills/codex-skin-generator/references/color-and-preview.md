# 配色方案与设计预览

## 配色输出

用户提供意图或设计图后，至少给出一个推荐方案；存在明显取舍时再给一个备选方案，不堆叠无差异色板。

使用以下结构组织结果：

```yaml
recommended:
  direction: "方案名称与一句话意图"
  colors:
    background: "#......"
    panel: "#......"
    panelAlt: "#......"
    accent: "#......"
    accentAlt: "#......"
    text: "#......"
    muted: "#......"
    line: "rgba(...) 或 #......"
  rationale:
    - "颜色与设计图或用户意图的对应依据"
  contrast:
    text_on_background: "比值或待实测"
    text_on_panel: "比值或待实测"
    muted_on_panel: "比值或待实测"
alternative:
  difference: "只有与推荐方案存在实质取舍时填写"
```

未声明 `appearance` 的历史主题仍把推荐方案写入 `theme.css` 的深浅固定选择器。新主题显式声明颜色模式时，`theme.css` 提供完整基础色板，`theme.light.css` 与 `theme.dark.css` 只写各自需要变化的增量变量；纯主题颜色角色使用十六进制颜色，备选方案保留在对话中。

新版默认选择双模式。用户保持默认时，先自动完成浅色和深色两套初稿，再展示配色依据并接受微调。两套初稿默认共用视觉方向、图片与强调语义，但分别建立适合各自亮度环境的背景、面板、文字、弱文字、边界和状态色；不得把一套颜色简单求反，也不得要求用户先逐项指定两套色值。模式 CSS 可以在用户明确要求时引用不同背景图片，但生成流程不主动提示这项高级能力。仅选择一种模式时，基础色板以该模式为可用回退，并只生成对应模式覆盖文件。

## 从图片建立颜色角色

1. 先识别大面积背景与主体，不把面积最大的颜色机械地当强调色。
2. 从设计图提取“关系”而非只抄色值：背景与面板的亮度差、强调色饱和度、边界强弱、文字冷暖。
3. 背景图较复杂时，面板使用足够不透明的表面色或遮罩；不要依赖图片恰好较暗的位置保证文字可读。
4. 强调色用于焦点、活动态和关键操作，不让所有表面都染成同一色相。
5. `accentAlt` 应承担次级强调或状态区分，不只是 `accent` 的任意亮度复制。
6. 图片无法查看或无法可靠取色时，明确标记为“按文字意图推断”，不要声称从图片采样。

## 可读性门槛

- 正文文字与背景/面板目标对比度至少 `4.5:1`。
- 大号文字和非文本控件边界目标至少 `3:1`。
- 弱文本仍需可读；若低于 `4.5:1`，只能用于非关键信息并在预览中明确检查。
- 焦点轮廓必须相对相邻颜色可见，不能只靠阴影。
- 错误、成功、警告不只依赖颜色表达，保留图标或文本语义。

静态校验器只会对可解析的十六进制颜色进行基础检查。透明叠加、背景图和渐变必须以渲染预览或真实页面为准。

## 预览产物

使用 `scripts/render_preview.mjs` 从实际皮肤目录生成独立 HTML。预览必须：

- v3 纯主题依次嵌入LokiMetis统一 CSS、当前 `theme.css`、已声明的模式 CSS 和变量引用图片；旧皮肤继续嵌入包内 CSS 与固定图片，不另造脱离成品的样式。
- 构建与 `component-map.yaml` 对应的模拟 Codex DOM，包括侧栏、顶部栏、首页、会话、拉取请求、站点、已安排、插件、设置、消息、编辑器和通用语义控件。
- 旧六文件兼容皮肤根据 `extensions.photoPanels` 渲染扩展面板；纯主题不得渲染扩展根或照片面板。
- 提供首页/会话和浅色/深色切换，便于检查状态样式。
- 在页面上显示“设计预览，不代表真实 Codex DOM 兼容性”的非遮挡标记。

生成命令：

```bash
node scripts/render_preview.mjs ./skin --output /tmp/skin-preview.html
```

需要固定首屏以便逐页截图时使用 `--surface pull-requests|sites|automations|plugins|settings`，需要固定浅色首屏时增加 `--mode light`。交互切换仍保留，但自动截图不得依赖点击时序。

## 预览检查

1. 桌面宽屏检查颜色角色、背景裁切、侧栏、顶部菜单和编辑器；旧六文件皮肤配置了扩展时再检查照片面板。
2. 窄屏检查文本换行、按钮尺寸、横向溢出和扩展隐藏。
3. 切换浅色/深色，确认不是简单反色且正文保持可读。
4. 逐项切换首页、会话、拉取请求、站点、已安排、插件、设置和 other，确认主表面、列表、分隔线、标签页、表单、空/错误状态与 `visibleOn` 符合设定。
5. 长标题、长说明和图片主体不得溢出或遮挡原生模拟控件。

如果有浏览器截图能力，输出至少一张桌面预览；用户关注响应式时再增加窄屏截图。若无法渲染，只交付 HTML 并明确未做视觉截图检查。

## 证据边界

设计预览用于验证设计系统和扩展构图，不验证 Codex 当前版本的真实选择器、Portal、虚拟滚动或交互生命周期。交付中分别记录：

- `静态校验`：文件、清单、脚本与配置合法。
- `设计预览`：模拟 DOM 中的视觉结果。
- `真实 Codex 验证`：目标版本中的实际注入与交互。

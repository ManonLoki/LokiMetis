# 从图片与描述推导皮肤设定

## 创建门槛

生成皮肤前必须取得以下四项：

| 必填项 | 规则 |
| --- | --- |
| 皮肤名称 | 用户可读名称，不自行虚构最终名称 |
| 皮肤说明 | 说明视觉意图、使用场景或主题；保存到 `theme.json.description` |
| 作者 | 用户明确提供的署名 |
| 期望风格 | 用户希望表达的视觉方向；用于推导颜色、背景和组件气质 |

用户已经提供的项直接复述确认，不重复询问。缺失项必须询问并等待；这些内容不能用启发式默认值跨过。第一轮只询问这四项，不同时要求主色、图片路径或颜色模式。

## 背景来源追问

收齐四项后再单独询问用户使用现有背景还是 AI 生成背景：

- 选择现有背景时才要求绝对路径，并确认文件是可读的真实 PNG/JPEG。效果参考不能静默顶替背景，除非用户明确说同一图片也作为背景。
- 选择 AI 生成时，根据期望风格生成适合大面积 `cover` 裁切、主体避开主要内容安全区的背景；保留原始生成结果，再按主题格式复制或转换。
- 图片生成能力不可用时说明限制并改为索要现有图片，不能继续使用蓝图占位图。
- 双模式默认共用一张背景，不询问是否分别提供。用户主动要求不同模式图片时，再分别取得或生成，并记录浅色与深色归属。

纯主题背景支持 PNG 或 JPEG；旧六文件皮肤固定主图仍要求 PNG。转换素材时保留原文件。

## 颜色模式默认值

新版主题默认直接适配浅色和深色，不再追问是否保持双模式。用户主动明确要求仅浅色或仅深色时再按其选择生成；不得根据效果图或系统当前模式静默改变双模式默认值。

保持双模式时，生成器负责先从同一视觉意图自动推导两套可用配色，不要求用户提供两套色值。两套方案应保持品牌与强调语义一致，同时分别处理表面亮度、文字对比、边界、背景遮罩和状态色，不得机械反色。

## 输入分类

先判断每份输入的用途：

| 类型 | 判断依据 | 处理方式 |
| --- | --- | --- |
| 效果参考 | 包含完整界面、示意排版或并非 Codex 尺寸 | 提取视觉规则，不直接作为背景 |
| 背景素材 | 用户明确要求使用，或图像适合大面积裁切 | 评估主体安全区、裁切与遮罩 |
| 组件素材 | 人像、海报、卡片图、Logo、纹理 | 分配给扩展或局部表面 |
| 混合输入 | 同一图片既表达效果又要求使用 | 分别记录“借鉴规则”和“实际使用方式” |

无法查看图片时明确说明限制，基于用户文字继续，不虚构图像内容。

## 推断顺序

按以下顺序推断，后项不得推翻前项的明确证据：

1. 用户明确描述与限制。
2. 图片中重复出现的视觉规律。
3. Codex 工作界面的可用性约束。
4. Skill 默认值。

从图片提取：

- `palette`：背景、面板、强调、文本、弱文本、边界、状态色。
- `surfaces`：扁平、描边、玻璃、浮雕、像素、金属或纸张等层级语言。
- `geometry`：圆角、直角、切角、线宽、间距和密度。
- `typography`：克制、终端、编辑、复古或展示气质；不要猜具体字体名称。
- `imagery`：主体位置、可裁切区域、适合 `cover` 还是 `contain`。
- `motion`：静态、轻反馈或持续氛围；缺省为轻反馈。
- `coverage`：仅换色、整体皮肤或包含扩展组件。

## 推断设计简报

实现前用下列紧凑结构总结，不需要创建文件：

```yaml
evidence:
  - source: user-text | reference-image | background-image
    observation: "可核对的事实"
decisions:
  visual_direction: { value: "...", basis: explicit | inferred | default }
  palette: { value: "...", basis: explicit | inferred | default }
  density: { value: compact | balanced | spacious, basis: inferred }
  background_usage: { value: direct | derived | none, basis: explicit }
  component_scope: { value: [sidebar, home, composer, thread, pull-requests, sites, automations, plugins, settings], basis: inferred }
  photo_panels: { value: disabled | configured, basis: default }
assumptions:
  - decision: "可逆默认项"
    confidence: high | medium | low
questions:
  - "四项必填、背景来源缺口，或会改变布局、素材使用权、扩展行为的问题"
```

## 追问预算

除四项必填缺口和背景来源选择外，一轮最多三个设计问题。只有以下情况值得追问：

- 效果图是否仅供参考，还是必须作为实际背景。
- 图片主体是否允许裁切或需要完整展示。
- 两个照片浮窗是否启用、展示什么内容、在哪些页面出现。
- 品牌、人物或版权素材是否获得使用授权。
- 用户要求的布局会遮挡编辑器或会话，必须在取舍中选择。

颜色微调、圆角、阴影、默认断点、面板间距等可逆细节不应阻塞；先给出推断方案并允许用户之后修正。

## 启发式默认值

- 未指定密度：沿用参考图；无法判断时使用 `balanced`。
- 未指定动效：仅 hover/focus 状态，尊重减少动态效果。
- 纯主题只有背景图槽位，不创建照片浮窗。
- 用户明确要求浮窗图片时，说明该能力只适用于旧六文件兼容皮肤；选择旧格式后，一张图片只启用一个面板，不复制。
- 旧格式提供两张浮窗图片时，默认在宽屏会话页分置左上和左下；窄屏隐藏。
- 用户只描述“做两个照片窗”：先提出可执行的两个面板推断，再最多追问内容含义、位置或出现页面中的关键缺口。

## 对话示例

用户：“参考这张图做成黑绿终端风，背景也用这张图。”

合适响应：先说明将图片同时视为风格证据和背景素材，推断高对比、紧凑、直角、轻量扫描线；若主体裁切风险不明确，只问“背景主体需要完整保留还是允许裁切”，其余直接继续。

用户：“左边放我的照片，下面再放一张海报，像老聊天软件。”

合适响应：将其解释为两个 `skin-extension` 照片面板，提出左上资料窗和左下海报窗、仅宽屏会话显示的默认方案；只在图片尚未提供或页面范围不明确时追问。

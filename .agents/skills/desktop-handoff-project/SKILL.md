# 恢复与交接项目

先读取用户级 `AGENTS.md` 与项目启动入口，按 [$desktop-task-workflow](../desktop-task-workflow/SKILL.md) 解析项目已记录开关；关闭时在当前聊天恢复，不自动创建左侧子树。已有 Task 沿原身份、结果和冻结环境主动修复并自动核对，继续已授权范围无需重复人工审批。普通诊断、局部设计、实现与开发回归可留在同一结果；仅用户明确要求时阶段隔离。恢复不扩大原授权，也不把开发回归当正式验收。

读取 [工程规则](../../../docs/ENGINEERING_RULES.md) 的记忆触发规则、存在的 [状态索引](../../../docs/project_status/README.md) 和存在的最新状态。恢复默认只读；保存状态只在索引规定的独立事件发生时执行。候选构建、E2E、完整验收与就绪变化不触发 tracked 状态。

## 执行

1. 确认唯一项目根、请求范围和恢复/保存模式；Harness 源只恢复自身工程。检查 Git 分支、HEAD 与工作区，保护未提交修改。
2. 读取最新状态及与当前问题相关的规格、ADR、技术债；只在存在未完成活动计划或本次真实需要协调时读取相关计划，不加载全部历史。要追溯完整沿革时转 `$desktop-summarize-development-history`。
3. 区分已确认、已实现、已验证、待定和阻断事实，区分当前修改与已提交结果。候选事实只读适用 `release/` 原子证据，不把计划、脚手架或旧快照当完成证明。
4. 恢复模式只在回复给出当前结果、阻断、最直接下一步、精确文件/提交/证据与授权边界；不写记忆，不自动执行下一生命周期阶段。
5. 保存模式须有真实交接、重要阻断、用户要求，或状态索引规定的本地 Git 发布后下一受管开发分支事件。直接保存请求先建立一次外层 `$desktop-implement-change` 上下文；已有调用上下文直接复用其分支、分类与提交责任，只写状态后返回，不重新执行完整实施流程。首次真实保存且索引缺席时建立中立索引；恢复无记录时只报告，不创建文件。按索引维护唯一当天文件，新日综合前一份仍有效状态形成完整快照，核对索引后删除被完全承接的旧日期文件。已打 tag 后不直接写脏发布主分支；实时 Released 只根据本地主分支、上下文和 tag 复核。
6. Work Plan 另满足其准入且确需协调时才交 `$desktop-plan-change`；不因交接自动产生 Todo、ADR、Changelog、Spec 或 Verification。候选事实不回写 Status 或 Plan。
7. 仅做必要事实、链接和差异核对，再返回原受管流程；不自动构建、E2E、发布、派发线程或执行外部操作。

## 输出

报告模式、项目/分支/HEAD、真实状态、未提交内容、阻断、下一动作及授权边界；保存时附状态文件和实际检查。没有历史或验证证据时明确说明。

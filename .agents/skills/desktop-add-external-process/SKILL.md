# 接入外部进程

读取 [外部进程合同](references/external-process.md)。先确认标准库、现有库或 OS 能力不足以完成当前闭环，再复用项目已有运行时。

## 执行

独立调用时先进入 `$desktop-implement-change`，在任何代码写入前完成其仓库、分支和适用版本门禁；已经由该流程调用时复用同一实施上下文，完成后返回当前步骤，不重复生命周期。

1. 从已批准需求确认外部程序及支持版本、发现方式、可执行路径/参数边界、超时、取消、输出上限和副作用；会改变产品边界的缺失事实交 `$desktop-define-product`。
2. 在具体驱动中用参数向量启动程序，在 core 解释标准化结果、执行领域流程并定义稳定错误；不把进程句柄暴露为领域 API。
3. 为子进程指定生命周期 owner，落实适用的超时、取消、输出限制和退出回收；成功启动不等于操作成功，不遗留 detached 进程。
4. 只接项目已选择的接口。CLI 才使用其 JSON/标准流/退出码与批准标志；其他 adapter 映射同一领域结果，不增加 CLI 或复制流程。
5. 运行 core 结果解释测试及受影响驱动/adapter 的非空回归，覆盖依赖缺失、非零退出和适用的超时、取消或参数失败；真实进程使用受控夹具。

## 完成

按 `$desktop-implement-change` 报告程序与参数边界、进程 owner、失败映射、实际测试及未验证平台。不自动执行产品外部操作、安装全局程序、构建或发布。需求移除或可靠库替代后删除能力专用驱动与特性。

# 准备 GUI 应用身份

GUI 初始化先建立经过用户选择的应用 Logo；首次真实 GUI 开发再补齐其余面向用户的应用身份。中性脚手架仍不得据此推测产品业务。

## 工作流程

1. 先判断调用模式。由 `$desktop-initialize-rust-project` 在选择 GUI 后调用时是“初始化 Logo 模式”：只读取当前项目展示名、ASCII 标识、`AGENTS.md`、`docs/ENGINEERING_RULES.md` 与已批准的可选品牌色/源资产，不要求 Product Spec 或 Product Status。首次真实产品 GUI 开发时是“完整身份模式”：再读取最新 Product Spec、Product Status、相关 ADR 和已有 `docs/GUI_APP_PROFILE.md`，确认产品目的已经批准并只补问缺失值。
2. 初始化 Logo 模式必须以三种明确不同的视觉方向发起正好 3 个候选生成请求，目标格式为 1024×1024 正方形无损 PNG，而不是三段文字提示或同图换色。发起生成前按请求顺序分配稳定逻辑标识 `candidate-1`、`candidate-2`、`candidate-3`；每个返回结果始终绑定原请求标识，不得按完成时间、文件名、摘要、风格偏好或工具返回后的任何属性重新排序。候选只使用当前项目展示名、当前初始化确需的视觉方向和用户有权使用的源资产；优先通过可用的图像生成能力实际生成三种方向，能力不可用或失败时使用**确定性备选方案**生成三种字母组合/几何构图。若用户选择**用户上传**，保留原图并生成三种留白/底色处理。
3. 用户选择前，候选只能以生成工具交付的原始字节位于本次任务精确拥有的临时目录；除预览工具显示图片所必需的读取外，不得检查文件类型、尺寸、色彩空间、透明通道、像素可见性、安全区、小尺寸辨识度、摘要或其他质量属性，也不得转码、缩放、裁剪、补边、改色、压缩、去元数据、重命名覆盖或执行任何标准化。把原始候选作为 3 张独立图片同时按 `candidate-1` → `candidate-2` → `candidate-3` 展示，不得使用拼图；后续重显、说明和选择问题必须保持同一顺序。某个候选生成失败时只重试原标识，不得移动或重编号其他候选。必须等待用户明确选择，不能静默采用第一张，也不能以中性占位图完成初始化。
4. 用户明确选择后，只对所选候选执行验证和标准化；拒绝的候选不得补做检查或处理。验证所选项能被安全解码后，按需把它标准化为 1024×1024、sRGB、保留安全区、避免细小文字且在 32×32 仍可辨认的无损 PNG。若标准化改变可见构图、颜色或边缘，必须再次预览最终母版并取得确认。把最终选中母版保存为 `<project-id>_gui/src-tauri/icons/app-icon-master.png`，逐字节复制为 `<project-id>_gui/public/app-identity/logo.png`，使用项目本地真实 Tauri `icon` 命令生成平台图标集，并确认 `icons/32x32.png` 为可见的 32×32 8-bit RGBA 非交错普通文件且由 `bundle.icon` 引用；选择系统托盘时，该文件同时是托盘图标来源。拒绝的临时候选可在最终母版、路径与摘要确认后清理，不得删除用户原始上传。
5. 选择完成后才创建或更新 `docs/GUI_APP_PROFILE.md` 的 Logo 证据，按稳定顺序记录三个逻辑候选标识、用户选择、所选项后置验证/标准化结果、母版/运行时/平台图标路径与摘要，以及仍待首次真实 GUI 开发确认的元数据；不得为未选候选补写格式、尺寸、摘要或标准化证据。必须保留 `$desktop-initialize-rust-project` 已确认的唯一 `gui-initialization-config` 围栏代码块：上游七字段仍按 `system_tray`、`system_notification`、`autostart`、`single_instance`、`deep_link`、`global_shortcut`、`sidebar_mode` 的相对顺序和值域解释，前六项只能为 `enabled`/`disabled`，侧栏只能为 `compact`/`detailed`；LokiMetis 在 `autostart` 与 `single_instance` 之间另外保留受保护的 product-owned `sponsor_page = enabled`，只由既有 GUI profile、ADR 与产品实现消费，不得被身份更新删除、改序或泛化为共享能力。除这项已批准扩展外不得含未列出的字段；`deep_link = enabled` 必须同时满足 `single_instance = enabled`。侧栏未选择时的 `detailed` 缺省必须已由初始化器写入，身份更新不得覆盖或再次推断这些配置。profile 的 UI 设计标准章节还要记录全部命中的稳定标识：通用标准固定为 `tauri-gui-common-v1`，侧栏 compact 为 `tauri-gui-sidebar-compact-80-v1`，detailed 为 `tauri-gui-sidebar-detailed-v1`。若用户批准像素或信息架构偏离，记录精确差异和关联 ADR；没有产品 ADR 的中性初始化不得写入自造偏离。初始化基线不得残留 `pending`、临时占位图或未选择状态。
6. 完整身份模式预览初始化所选 Logo，让用户选择保留或重新走“自动生成 / 确定性备选方案 / 用户上传”的三候选流程；重新生成时同样执行稳定标识、原始顺序预览和选择后才验证/标准化的规则。随后确认应用展示名称、简短描述、应用标识符或包标识符、图标方向，以及任何品牌色或源资产。主窗口标题不是自由文案：记录并预览固定公式 `{applicationName} v{version}`，其中应用名来自本资料、版本来自权威打包元数据；不得附加联系人或保存会漂移的手写版本标题。
7. 若批准的分发格式包含 macOS DMG，展示初始化生成的 `<project-id>_gui/src-tauri/dmg/background.png`，再让用户批准该中性基线或替换它；同时确认文案语言、660×400 DMG 安装卷窗口尺寸和应用/Applications 落点。批准基线时保留现有字节，替换时把最终 660×400 PNG 写回同一路径并重新展示。软件许可页只按产品/渠道明确要求决定；不得复用 Harness、其他产品或带第三方身份的图片。
8. 在完整身份模式补全 `docs/GUI_APP_PROFILE.md` 的已批准值、固定标题公式与权威字段来源、应用 Logo/图标来源与溯源、母版/运行时/平台路径及 SHA-256、DMG 背景路径/摘要/尺寸/落点/文案语言和未解决分发元数据。只有身份选择构成长期重要决定时才写 ADR；只有下游真实渠道发布、重要阻断、跨会话交接或用户要求时才更新 Product Status，候选构建、E2E、完整验收和就绪复核只把事实写入忽略的 `release/` 原子集合及最终回复。
9. 将资料直接交给 `$desktop-add-gui-adapter`：选中 Logo 必须接入平台图标和侧栏顶部，当前版本紧随 Logo 下方；仅当 `system_tray: enabled` 时还接入托盘并把 `default_window_icon()` 当作必需值。更新显示名后验证平台图标、侧栏 Logo、原生标题、`document.title` 与设置页应用/版本来源，并确认标题和应用元数据没有联系人。系统托盘、系统通知、开机自启、单实例、深链接和全局快捷键均以上游七字段为准，身份 Skill 不得自行启用；LokiMetis 的 `sponsor_page` 只保留受保护产品实现已有的 `/settings` 底部微信支付/支付宝双码区，不由身份 Skill 创建 `/sponsor` 路由、导航、模板或二维码资产。

## 边界

- 不得静默复用 Harness 徽标、其他产品图标、生成草稿或用户上传的低分辨率文件作为选中 Logo、正式发布图标或 DMG 背景。
- 不得虚构商标权属、商店元数据、签名身份、发布者身份或法律声明。
- 选择生成或编辑图标时，必须使用可用的图像生成或编辑能力；如果该能力不可用，则必须实际生成三种确定性备选方案，不得假装已经生成。
- 候选生成目标不等于选择前验证结论；在用户选择前不得因为想证明目标格式、质量或可见性而读取或改写候选。
- 本 Skill 在 GUI 初始化时先触发 Logo 模式并在初始化后保留；首次产品 GUI 开发时进入完整身份模式，此后只有已批准的 GUI 身份发生变化时才再次触发。

## 完成输出

报告三个原始候选的稳定预览顺序、用户选择、仅对所选候选执行的后置验证/标准化、母版/运行时 Logo/平台图标证据、`icons/32x32.png` 的格式/可见像素/配置引用与摘要、已批准和未解决的元数据、资料位置、打包阻断项，以及下一项 GUI 实施操作。不得报告未选候选的格式、尺寸、摘要或标准化结论。

# 实施变更

完成当前授权范围，以“实现 + 本次必要单元测试 + 事件触发记录”为日常开发的完整闭环。

## 工作流程

1. 检查 `AGENTS.md`、`docs/ENGINEERING_RULES.md`、Git 根、当前分支与工作区，只读取本次变更直接需要的 Product Spec、ADR、GUI profile 或技术事实。若当前根仍是 Harness 源，只允许维护 Harness 自身规则、Skills、中性资产、脚本、验证器、文档或交付工程；产品目的、业务功能、专属 UI/文案/数据、远程地址、凭据、构建与发布需求留到终端下游处理。保护用户已有修改，重叠无法安全处理时停止。
2. 对已初始化下游先调用 `$desktop-manage-version plan` 只读分类并取得 `required_version`：新功能使用 `feature`，具有新稳定 ID 的问题修复或用户可感知优化统一使用机器分类 `bug-fix`，用户批准的显式 Major 使用 `major`；查询、诊断、复现、未完成或重复处理、行为保持重构、内部优化、测试补强、文档、格式和内部清理使用 `maintenance`。分类二义性会改变产品范围或版本时先确认。
3. 直接实现用户请求。多步骤、多模块、中等风险或可并行本身不触发 Work Plan、候选构建或完整验收；只有用户明确要求持久计划、跨会话交接，或发布/高风险工作确需协调时才调用 `$desktop-plan-change`。
4. 日常开发先运行本次必要测试，不做环境预检。只有真实测试命令已失败，且退出状态和脱敏诊断明确表明缺少或不兼容的受管工具链/系统依赖时，才调用 `$desktop-check-development-environment`，成功后重试原命令一次。纯文档或元数据任务不增加环境步骤。
5. Core-first 是硬规则。接口与宿主无关的领域类型、业务规则、语义校验、默认值、用例编排、状态转换、稳定错误、平台无关权限、迁移和持久化策略必须在 core；GUI adapter 只拥有 Tauri/React 装配、IPC 结构校验、展示与纯交互状态、桌面宿主机制、调用 core 和结果映射。修改 GUI adapter 前确认“GUI 操作 → core API → core 测试”映射；仅修改布局、IPC 映射或桌面宿主机制时记录其专属性理由。
6. GUI 交互 handler 必须绑定在实际拥有动作的按钮、链接、`Switch`、`Checkbox` 或菜单项本身，不能由 Card、表格行或单元格代理。需要跨路由恢复的页面工作状态由应用根 Jotai store 的模块级 atom 在当前进程内保存，不得持久化或镜像 Query/core 数据；成功空页只在当前页大于 1 时回退第 1 页，加载与错误不回退。
7. 代码行为变化增加或更新相关非空单元/回归测试：业务行为先覆盖 core 的核心成功路径与最高风险失败路径，再覆盖本次 GUI 映射；缺陷修复必须增加能复现问题的回归。纯文档、元数据、格式或不可合理单测的机械变更只运行解析或差异完整性所需的最小检查。
8. 只运行本次变化需要的测试或检查并立即修复失败。日常开发不得自动追加格式化、lint、静态、全仓测试、构建、冒烟、E2E、Verification 或人工复核；501–1000 行前端和 501–2000 行其他人工维护文本的软职责复核只在明确发布且当次 `reviewSelection: enabled` 时集中执行。这些步骤只由当前变化、用户明确请求或专用门禁触发。
9. 相关测试或最小替代检查通过、变化确实完成后，使用与第 2 步相同的参数调用 `$desktop-manage-version apply`。功能在同一正式发布周期只由首个功能提升一次 Minor 并锁到真实发布成功；问题修复或用户可感知优化的每个独立 `bug-fix` 稳定 ID 提升一次 Patch 且不受功能锁影响，重复 ID 返回幂等结果。新生成 Minor/Patch 采用 `0..99` base-100 自动进位；自动进位到 Major 是数值例外，显式 Major 仍需用户批准。测试失败、实现未完成、查询/诊断/复现或其他 `maintenance` 情况不得提升版本。
10. 只更新被独立事件触发的记忆：产品范围变化更新 Product Spec；长期决定或硬规则例外写 ADR；合格的可感知变化写 Changelog；重要阻断/交接、真实渠道发布后的受管记录阶段、审计或用户要求再写相应状态、计划或验证记录。候选构建、收集、E2E、完整验收和就绪复核只把事实写入忽略的 `release/` 原子集合及最终回复；未触发时不创建占位文件，也不写占位记录。
11. 若用户提供活动计划，只更新与本次实现直接对应的 Todo。普通工作在当前 Git working tree 完成；只有用户明确要求提交时才调用 `$desktop-configure-git-commits` 并创建普通提交，不自动建立额外工作目录、分支流程或发布操作。

## 边界与输出

- 实施授权不授权破坏性迁移、凭据使用、签名、发布或其他新外部副作用。
- 单元测试只证明本次代码单元行为，不代表真实候选可用、完整验收或发布就绪。
- 报告变更分类、稳定 `change_id`、`required_version`、是否实际提升及幂等原因、实际运行的测试/最小检查、未执行项和剩余风险；只有用户要求的活动计划存在时报告 Todo 状态。

# 管理项目依赖

读取 [Rust 技术基线](../../../docs/RUST_CLI_TEMPLATE.md) 的所选接口、工具链和依赖准入章节，以及 [工程规则](../../../docs/ENGINEERING_RULES.md) 的依赖规则。版本数值、固定技术族与锁策略以这些事实源和当前根清单为准，不在本 Skill 复制维护。

## 执行

1. 确认已批准能力、目标平台和实际依赖变更。优先标准库和项目已声明依赖；新增第三方运行时依赖确有必要时，解释原因并取得授权，初始化已确认接口的固定依赖或当前会话已批准的依赖复用授权，不重复询问；显式声明在项目本地隔离环境中，不假设或安装全局第三方包。
2. 初始化复用初始化上下文；已初始化项目直接调用时，任何写入前先进入 `$desktop-implement-change` 的同一生命周期。已经由该流程调用时不重复分支、版本或提交。
3. 按权威准入规则查询官方 registry 的稳定候选与官方 API，核对实际用途、最小 features、最低工具链、peer、目标平台、安全和产物影响。固定技术族不重新选框架；最新候选不兼容时记录依据再逐次选择。不得把模板旧下界当作当前 registry 查询结论。
4. 根 workspace 集中声明 Rust 第三方与内部路径依赖，成员复用 `workspace = true`；其他语言在项目自身清单显式声明。缺失/初始化/运行失败映射为稳定错误，按所选接口映射，只有 CLI 才涉及退出码。
5. 复用 [锁策略模块](../desktop-implement-change/scripts/project_lock_policy.mjs) 的 `readDependencyLockPolicy`、`assertDependencyLocks`；它是库而非 CLI，不执行版本选择。遵守 `ignored`/`tracked` 的真实声明，未知值失败关闭，跟踪锁才冻结解析。构建只读检查锁，不进入本依赖更新流程。
6. 新增或提高下界时按基线在临时副本验证最低直接版本，并在根清单声明的最低工具链执行受影响非空测试；前端按规则执行最低环境的类型、测试和生产构建。这是依赖准入的必要验证，不将临时配置写回产品。较新编译器成功不证明 MSRV；不为追逐版本号升级可用工具。
7. 返回原实施流程，仅更新真实受影响清单、锁文件及已触发记录。不改发布版本、CI pin、摘要或工具数字来凑依赖范围。

## 输出

报告标准库/现有依赖不足的理由、候选兼容依据、实际下界和特性、清单/锁变化、最低环境真实验证，以及未验证平台。失败不能被计划或普通最新环境成功替代。

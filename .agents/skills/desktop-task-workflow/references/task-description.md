# Task 描述模板

以下为规范模板。以当前结果真实事实替换占位内容，删除不适用的可选项目或明确写 `Not applicable`；不为了填模板扩大范围或增加人工门禁。

```markdown
目标：
一个明确、可核对的结果及完成条件。

Task 绑定：
- 稳定 Task key、项目内预留序号及初始标题。
- Codex 项目名称、projectId、hostId 和保存项目完整路径。
- user_owned_tasks 的已记录值与本次新建来源。
- task_worktrees 的项目值、冻结环境和规范化 cwd。
- Git 时记录 repository common-dir、起始 branch/HEAD；非 Git 为 Not applicable。
- Git feature summary：独立 ASCII kebab-case 技术摘要，不从显示标题推导。

输入与依赖：
- 当前任务输入的精确提交和已有证据；依赖其他结果时注明等待条件。
- 只有用户明确要求阶段隔离时填写固定阶段和前序结果。

实施范围与所有权：
- 允许修改的非重叠路径、预期行为和必要相关检查。
- 已有用户修改、共享文件和需要串行处理的冲突。
- 禁止范围及未授权的发布、远端、凭据或系统副作用。

授权继承：
- 复用用户对本结果的资料阅读、实施、同范围修复、必要开发检查和适用本地提交授权。
- 自动完成真实身份、项目、cwd 和输入检查，通过后直接执行，无需重复人工审批。
- 继承宿主实际权限；不得伪造批准、提权或绕过工具拒绝。
- 独立 Worktree 按所有权并行；同一 Local cwd 串行。
- 你不是独占代码库，不撤销其他 Agent 或用户改动。

阅读与执行：
- 用户级 AGENTS.md、项目 AGENTS.md、desktop-task-workflow 及本目标精确命中的事实源。
- 普通实现按 desktop-implement-change；Git 首次写入按生命周期 start 创建登记分支。
- 仅运行本次结果必要的非空开发回归或替代检查，不自动增加正式验收、E2E 或发布。

交付：
- 真实 Task/环境身份、结果、变更文件、分支/提交、实际检查、未执行项和剩余风险。
- 真实转换时同步四态进度；结果与必要检查及适用提交完成才标已完成。
- 保留其他任务资源，清理只在明确请求且精确身份复核后执行。
```

# GPUI 原生桌面能力与配置询问

本文件管理 GPUI 能力的实现边界与选择后的配置问询；九项开关仍以 `docs/GUI_APP_PROFILE.md` 的 `gui-initialization-config` 为唯一事实。Tauri 继续使用各自的能力 Skill，不混装 Tauri 插件。

## 选择后的询问

初始化先按既有顺序解析九项配置。所有能力选择结束后，必须汇总已选的托盘、系统通知、开机自启、单实例与全局快捷键，询问是否需要协助配置；不能仅给出一句“以后可以配置”。已明确提供的答案直接复用，禁用项不问，整组没有启用项时跳过。

Harness 源只确认中性能力及其固定边界。产品动作、通知内容、键位、额外托盘菜单和自启隐藏启动等产品配置，只能在实例化完成、切换到终端下游唯一根目录后询问和实施。用户选择继续配置时把这一步纳入真实下游移交，不把配置请求丢弃，也不在模板源记录产品内容。

| 已选能力 | 在终端下游询问 | 未明确配置时 |
|---|---|---|
| 系统托盘 | 是否沿用显示窗口/退出菜单与关闭隐藏；如需额外菜单，逐项确认用途、可见名称与对应动作 | 仅固定双语菜单；托盘创建失败允许正常关闭，不能隐藏到不可恢复状态 |
| 系统通知 | 哪些已批准事件需要通知；是否需要点击返回原窗口；说明应用偏好、OS 权限与实际送达的区别 | 应用偏好关闭；没有产品触发器、测试消息或启动时权限请求 |
| 开机自启 | 是否需要协助在设置页开启登录自启；是否保持正常显示窗口 | 只提供设置入口，不注册登录项；实际状态以 OS 为准；隐藏启动另需托盘及可恢复路径 |
| 单实例 | 再次启动是否沿用恢复并聚焦已有窗口；如需处理启动参数，先确认具体场景 | 第二进程只唤醒已有窗口后退出；不转发参数、文件或业务载荷 |
| 全局快捷键 | 每个动作的用途、初始按键或未绑定、固定/可编辑、界面位置与可安全测试方式 | 唯一 `gui-global-shortcut-contract` 为 `{"schemaVersion":1,"actions":[]}`；零默认键位、零 OS 注册和零占位界面 |

一次只询问一个尚未明确的相关问题。先解释用户可见行为并提供建议选项，再处理实现细节。选择能力不授权修改当前开发机器的登录项、通知权限或热键；真实宿主测试按初始化/候选要求记录并恢复原状态。

配置只能写入下游 profile 的专用块及对应产品事实，不能添加第十个初始化字段或 Agent Policy frontmatter 字段。全局快捷键继续独占既有 contract；未获明确绑定时保持空数组。

## 系统通知官方接口

2026-10-09 核对 [GPUI Kit SystemNotification](https://gpui-kit.com/docs/system-notification/) 与 [gpui-kit 0.7.1 API](https://docs.rs/gpui-kit/0.7.1/gpui_kit/)。复用已经声明的 GPUI Kit，不另装通知 crate。启动在 `gpui_kit::init` 后、打开窗口前设置与打包身份一致的 `set_app_identity`。

原生投递使用 `App::show_system_notification(SystemNotification { tag, title, body, actions })`；仅已批准产品路径可调用，内容有界且不进入日志。返回 `()` 只证明提交，不证明 OS 授权或送达；应用偏好不代表系统权限。中性初始化不发送通知，不覆盖 Kit 安装的全局响应处理器。

macOS 真实投递需要已打包的 `.app` 和系统许可，普通调试进程不作为横幅证据；Windows 需稳定应用身份；Linux 需会话 D-Bus 和通知服务。当前 Linux 上游不支持 tag 替换/撤回，并在投递时使用上游内部线程；不宣称这些线程由 Harness 回收。若产品要求可查询权限、送达结果、动作回执或更严格任务回收，必须先核实官方 API，再确认具体原生桥与项目本地依赖，不能伪造成功状态。

## 参考与依赖边界

托盘、自启与单实例参考既有对照工程的接线设计，抽取并中性化其窗口恢复等宿主模板，其余接线按可停止 worker 和条件生成规则调整，不复制产品代码、身份、资源或业务菜单。参考中的窗口内 GPUI KeyBinding 不等于后台全局快捷键。

原生托盘、登录项、本地 IPC 和后台热键不能靠标准库与当前 Kit 完整替代；新增第三方 Rust 依赖需先说明理由并取得用户同意。Helper 始终只用 Node 标准库；依赖只按启用能力加入下游 Cargo 工作区，不做全局安装。平台能力缺失或尚未验证必须明确报告，不能以文件生成或单元测试冒充真实宿主结果。

当前托盘和后台热键限 macOS/Windows；Linux 热键后端不能可靠报告注册失败，因此当前不启用。Windows 热键库内部释放监听线程不暴露 join；Harness 只拥有管理器、绑定和自身轮询 Task，不宣称回收第三方内部线程。Windows 前台策略可拒绝抢焦点，此时恢复显示并闪烁提示。自启在 Windows 仅操作 HKCU，不调用上游会删除 HKLM 的 disable；含空格路径加引号，macOS XML/Linux XDG 无法安全编码的路径在写入前失败关闭。

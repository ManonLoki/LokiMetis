# Linux 原生宿主方案

只在修改Linux窗口、托盘、通知或热键机制时读取。这里收录已有产品验证过的工程做法；中性renderer仍拒绝生成Linux托盘/热键，产品实现不能据此改判为模板已支持。当前产品方案、精确版本和验证状态统一取[Linux工程知识库](../../../../docs/LINUX_GPUI_TOOLCHAIN.md#已验证能力与证据索引)。

## 图形会话与窗口

启动前捕获会话能力；产品需要全局定位/置顶且存在`DISPLAY`时可以选择X11/XWayland，不改写进程环境。纯Wayland普通toplevel不能承诺同样的全局定位和置顶；未实现协议路径明确失败并保留恢复入口，不能用激活代替置顶。

X11使用真实XID及checked request。几何以root全局物理坐标保存，仅在原生边界转换DIP；工作区取RandR活动显示器与当前桌面`_NET_WORKAREA`交集，缺协议时才回退root几何。混合DPI及热插拔需单独实测。

EWMH置顶是窗口管理器协商状态。首次map后重新请求并异步读回，以实际覆盖关系验证；轮询有总预算且不阻塞主循环。确认后释放临时几何/显隐目标，避免旧目标拦住拖动或单独切换穿透。Shape Input与视觉区域分别拥有；写后读回，失败尝试恢复，恢复失败保留未知状态。只有原生效果确认才提交偏好；退出接管已接受但尚未提交的最后意图。

## 托盘与关闭恢复

KSNI/StatusNotifierItem使用会话D-Bus，不在GPUI主线程混入GTK循环。创建对象不证明能恢复：后台有界worker联合核对Watcher存在真实host、注册列表包含本进程拥有的服务，以及精确托盘Id。owner变化、注销、断连或未知结果撤销旧的可用性；主线程只读已发布事实。

关闭回调已经借用当前GPUI窗口，不可在其中再次update同窗以取得XID。在安装机制时捕获所需原生能力，关闭及延迟隐藏阶段仍重新核对恢复入口；缺少可靠入口时允许正常关闭，不能隐藏到不可恢复状态。最终验收操作真实托盘恢复/退出，D-Bus属性读回不代替点击。

## 托盘与任务栏协同

只有产品明确选择“可靠托盘接管后隐藏任务栏入口”时才采用；中性窗口不默认增加该行为。X11/XWayland 主窗仍保留普通窗口类型，按当前恢复入口申请 `_NET_WM_STATE_SKIP_TASKBAR`；入口失效则撤销该意图并恢复已隐藏主窗。纯 Wayland 没有这条 EWMH 路径，保留普通入口，不为隐藏任务栏擅自切换后端。

依照 EWMH 的窗口状态合同，只有撤回窗口可以由客户端准备初始 `_NET_WM_STATE`；`UNMAPPED` 本身不证明撤回，还要核对 `WM_STATE`，最小化窗口仍归窗口管理器管理。读取属性时确认类型、格式及完整性，只增删目标 atom，保留最大化、置顶等其它状态。已管理窗口向 root 发送 ClientMessage，不能直接覆盖窗口管理器拥有的状态属性。

窗口管理器可能在撤回或重新 map 时删改状态。显窗前准备允许写入的初始状态，map 后无条件补发请求，并使下一轮托盘同步重发；常态只在恢复入口变化或请求失败时发送，避免持续访问 X11。缓存表示“已发送意图”，不是窗口管理器已应用的状态；失败后连旧缓存也失效。协议回执、状态读回和真实任务栏/Dock 呈现分别取证。


## 登录项与隐藏启动

自启能力的授权和串行 OS 读写继续由 [$desktop-add-gpui-autostart](../../desktop-add-gpui-autostart/SKILL.md) 管理。读取登录项须跟实际写入驱动使用同一路径解析，不能凭 XDG 规范猜测库的实现：已核对的 `auto-launch 0.6.0` 使用 `dirs::home_dir()` 下的 `.config/autostart/<app-name>.desktop`，没有读取 `XDG_CONFIG_HOME`；直接使用 `HOME` 会漏掉库的 passwd 回退。更换驱动或版本时重核源码，不能据此把这个布局变成全部 Linux 应用的规则。

库的 `is_enabled()` 可能只检查文件存在。需要确认当前启动目标/参数时，有界读取本应用条目，区分缺失、权限失败、无效 UTF-8 和超限；只接受主 `[Desktop Entry]` 组中唯一的完整 `Exec`，核对与写入端相同的命令编码及全部参数，并尊重 `Hidden=true`、`X-GNOME-Autostart-enabled=false`。重复主组/Exec 是歧义，不能当开启。不得把受限解析器当作通用 Desktop Entry 解析器，未覆盖的桌面执行条件仍须披露。

查询旧副本、无标记或被禁用的条目保持只读，不在启动时自动迁移。当前命令未启用不等于旧登录项不存在；用户明确重新开启时才更新本应用条目，明确关闭时仍须清理会继续执行的本应用旧项。迁移或真实开关的宿主测试前保存完整原字节/参数，测试后恢复，不只记录布尔值；用户明确请求的设置变更按请求保留结果。

隐藏登录启动仅在下游明确批准、且已有可靠恢复路径时接入。用本次进程的精确启动参数识别来源，不从“已开启自启”、父进程或近似参数推断；标记、注册命令和读取比较来自同一合同，不预置产品参数。托盘异步就绪时以有限总期限等待真实恢复入口，超时、失败或能力不支持就显示窗口；手动打开仍显示，重复登录启动是否唤醒现有实例按已批准行为明确处理。

`show=false` 只是创建意图，须核对当前 GPUI 后端是否仍在首次创建时 map。若有首次映射问题，按 [兼容补丁合同](../../desktop-manage-gpui-dependencies/references/compatibility.md) 定位精确版本，单独覆盖首次 map 次数及后续显窗，不把下游补丁复制成通用默认。完整登录过程、托盘丢失与恢复、纯 Wayland 和实际桌面呈现仍需目标宿主验证。


注册列表的服务/路径可能使用 KDE 的 `service/path`、GNOME 的 `service@/path` 或只有服务名；按标准对象路径解析后核对进程归属和精确托盘 ID。托盘失效后的显窗请求只有成功后才清除隐藏事实，失败保留恢复状态；手动打开或退出撤销旧延迟隐藏代次。

## Dock与桌面身份

窗口`app_id`、桌面文件标识、`StartupWMClass`及图标名应来自同一产品身份。已批准Logo派生窗口ARGB图标及真实尺寸hicolor PNG；`_NET_WM_ICON`读回只证明窗口属性，Dock还需能解析有效`.desktop`和`Exec`。隔离解包运行时，宿主未必能访问包内路径；临时宿主映射必须精确登记并恢复。最终包解包检查和真实Dock呈现分别取证。

## freedesktop通知

固定会话服务`org.freedesktop.Notifications`的`GetCapabilities`只证明服务可用；该协议没有每应用授权查询。不可达和超时不伪装为用户拒绝。启动不投递测试消息，实际发送遵守应用偏好及core事件规则。

worker拥有有界提交邮箱与通知ID映射，连接、认证及调用共享总预算。关闭、权限暂停和退出撤销未提交命令；确定拒绝和未知回执分别处理，超时不盲目重投。服务唯一owner变更后丢弃旧ID，只处理本owner已发送通知的`default`动作；未知动作不恢复窗口。正文按纯文本转义，通知桌面入口及图标沿用产品身份。API Accepted、真实横幅与点击恢复分别验证。

## 热键与回归边界

Wayland全局快捷键需要GlobalShortcuts Portal及真实系统授权；X11注册需要checked request和确定错误传播。`global-hotkey 0.8`的Linux断连回执不能当可靠注册成功。依赖声明及空action合同不构成后台服务或按键验证，也不授权注册键位。

协议回归使用owned私有D-Bus daemon，不改变用户session bus；真实X11测试的ignore状态不等于已执行。按改动选择`native/tray_linux_tests.rs`、`native/notifications/linux*_tests.rs`、`pet/host/linux_tests.rs`及`native/linux.rs`中的相关回归；完整候选再覆盖真实桌面交互。产品源路径位于`loki_metris_gui/src/`，其他下游使用各自对应模块，不复制产品状态或业务规则。
